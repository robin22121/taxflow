# 위하고 T · 홈택스 · 위택스 원천세 자동화 RPA (자동화 전용 노트북)

> **2026-09-15 최종 정리.** 직원은 자기 PC·자기 아이디로 이지원천에서 급여를 확인하고 **전송**만 누른다.
> **자동화 전용 노트북**이 세무사 전용 아이디로 위하고 T에서 **급여 입력 → 원천세 작업 → 지방세 작업**을 마치면
> 이지원천에 알림이 가고, 세무사가 **신고**를 누르면 노트북이 **홈택스 원천세 → 위택스 지방소득세**를 순서대로 신고한 뒤
> 접수증·납부서를 이지원천 조회·사장님 포털에 반영한다.
>
> - 위하고·홈택스·위택스 아이디/비밀번호는 **노트북에만 암호화 저장** — 이지원천 서버에는 저장하지 않는다.
> - **사원등록(입·퇴사·인적사항)은 자동화하지 않는다** — 민감정보이므로 직원이 위하고에 직접 입력하도록 안내한다.
> - 같은 날 오전의 A안 (i)(세무사 PC 크롬 익스텐션·세션 재활용·크레덴셜 저장 X)은 본 문서로 대체한다. 약관 4벽 분석(§1)은 유지한다.

## §1. 약관 검토

결정 축은 **데이터 위치**:
- **A안 (설치형·로컬 완결)**: 위하고 raw 데이터가 세무사 사무소 기기를 벗어나지 않음. 이지원천은 세무사의 도구.
- **B안 (클라우드형·서버 경유)**: 위하고 raw 데이터가 이지원천 서버에 저장·처리되고 서버가 위하고에 접속.

### 1-1. B안이 T 약관·일반약관에서 동시에 막히는 4가지 벽 (유지)

| 벽 | 조항 | B안이 위반하는 이유 |
|----|------|-------------------|
| ① 회원 자격 | T 개별약관 제2조 3호 | 이지원천(주식회사 호미)은 세무사·회계사 아니라 T 회원 자격 없음. B안은 필연적으로 세무사 계정 대여 |
| ② 계정 대여 금지 | 일반약관 제5조 ①, 제28조 | 서버가 세무사 계정으로 위하고에 접근 = 실질적 계정 대여 |
| ③ 인증수단 관리 의무 | T 개별약관 제10조 ② 2호 (전자금융거래법 용어) | 크레덴셜을 서버에 두면 안전 관리 의무 위반. 홈택스 공동인증서까지 확장하면 정면 충돌 |
| ④ 재위탁 동의 | T 개별약관 제3조·제4조 | 수임처→세무사→더존→이지원천 4단계 재위탁 발생. 수임처마다 개별 동의 필요 → 영업 불가 |

### 1-2. 현재 구성이 4벽을 통과하는 논리

| 벽 | 현재 구성 | 평가 |
|----|----------|------|
| ① 회원 자격 | 아이디는 T 회원인 **세무사 사무소 소유** (자동화 전용 세무사 아이디). 이지원천은 위하고 아이디를 갖지 않음 | 통과 논리 유지 |
| ② 계정 대여 | 이지원천 **서버는 위하고·홈택스·위택스에 접속하지 않음**. 사무소 소유 노트북에서 사무소 소유 아이디로 접속 | 도구 사용 논리. 단 로그인까지 도구가 수행 → §1-4 |
| ③ 인증수단 관리 | 제3자 서버 보관 X. **회원 본인 기기에 암호화 보관** (Windows 자격 증명 관리자 + BitLocker, §8-2) | 브라우저 비밀번호 저장과 유사한 수준. 노트북 보안 조건 준수가 전제 |
| ④ 재위탁 | 위하고 원본 데이터(신고서 파일·위하고 계산값)는 서버 저장 X. 서버로 가는 것은 **상태와 대조 결과(일치/차이 항목)**뿐 | 급여대장은 이지원천 자체 자료, 접수증·납부서는 홈택스·위택스 결과물 (위하고 원본 아님) |

### 1-3. 현재 구성에서 유리하게 작용하는 조항 (유지)

- **T 개별약관 제11조** — 회원이 입력한 데이터의 지식재산권은 회원. 세무사가 자기 데이터를 자기 도구로 처리 → 정당
- **T 개별약관 제12조 ④** — 회원 업로드 방식에 대한 위하고 책임 없음. 자동화 업로드는 회원 자유
- **T 개별약관 제10조 ①·제12조 ①** — 위하고 T 자체가 스크래핑 사용을 약관에 명시·면책. 협상 카드 ("귀사도 스크래핑 사용")

### 1-4. 남은 쟁점 (변호사 검토 필수)

- **실행 주체 해석 — 가장 큰 쟁점.** 오전 A안 (i)(세무사 세션 재활용)과 달리 **로그인부터 제출까지 이지원천 소프트웨어가 수행**한다. "사무소 설치형 도구"(노트북·아이디·자격증명 모두 사무소 소유·관리, 실행은 사무소 직원·세무사의 버튼) 구조를 계약·화면 문구에 명확히 한다
- **로컬 암호화 저장 후 자동 로그인**이 T 개별약관 제10조 ② 2호 "인증수단 안전 관리"에 부합하는가
- **일반약관 제8조 ② "대리인" vs T 개별약관 제10조 ② 1호 "임·직원"** — 상충 시 개별약관 우선, 병존 해석 시 일반약관의 대리인 조항 살아있음. 후자가 유리
- **홈택스·위택스 이용약관**의 자동화·로그인 정보 저장 관련 조항 — 미검토
- 공동인증서 비밀번호 자동 입력 — PoC 0에서 **홈택스 로그인에 세무법인 공동인증서 비밀번호가 필요**함을 확인 (§9-2). 자동 입력을 범위에 넣을지 결정 필요, 넣는다면 인증수단 관리(벽 ③) 쟁점으로 함께 검토

### 1-5. 두더지잡기 경고

T 개별약관 제10조 ① 은 "개별 기관의 스크래핑 관련 정책 변경" 을 명시. 더존조차 UI 업데이트로 대응 중. 이지원천도 같은 부담 — 셀렉터를 에이전트 코드 한 곳에 모으고, **셀렉터 실패 시 즉시 알림 + 수동 처리 안내**로 수정 사이클을 짧게 유지한다.

## §3. 아키텍처

```
[직원 PC — 개별 아이디]                    [이지원천 서버 (NHN)]
 크롬: 이지원천 · 위하고 T (직원 아이디)  ⇄   작업 큐 (rpa_jobs) · 감사 로그
                                             급여대장 엑셀 API
                                             신고결과 저장 (ClientFilingResult)
                                             알림 · 사장님 포털 · 납부안내 문자
                                                  ▲
                                                  │ 노트북 → 서버, 나가는 HTTPS 폴링만
                                                  │ (사무실 방화벽 개방 X)
[자동화 전용 노트북 — 세무사 전용 아이디]         │
 ├ Windows 전용 계정 + BitLocker                  │
 ├ Windows 자격 증명 관리자: 위하고·홈택스·위택스 ID/PW (암호화)
 ├ 에이전트 (Python) ─────────────────────────────┘
 │    └ Playwright connect_over_cdp
 └ 크롬 (--remote-debugging-port, 에이전트 전용 프로필)
      ├ 위하고 T
      ├ 홈택스
      └ 위택스
```

### 3-1. 자동화 방식

| 방식 | 평가 |
|------|------|
| **CDP 연결 (Playwright `connect_over_cdp`)** | **우선.** 노트북이 전용 기기라 크롬 실행 옵션의 UX 마찰이 작다. 새 크롬 실행보다 자동화 표시가 적다. `rpa-agent` 코드(서버 통신·실패 처리·수임처 대조·자격증명 저장) 재사용 |
| 크롬 익스텐션 (노트북 크롬) | **대안.** CDP가 감지될 때 전환. 페이지 이동 간 상태 유지·파일 전달 구현 부담 |
| 새 브라우저 실행 (Playwright `launch`) | **비권장 — 기술적 이유.** 자동화 표시로 감지·보안 프로그램 충돌 위험. 오전에 "약관 위반"으로 분류했으나 정확히는 "위반 소지"였고, 전용 아이디·노트북 로컬 저장 조건에서는 약관 우려가 완화됨 |
| 위하고 내부 API 직접 호출 | 비권장. 봇 감지가 가장 쉽고 비공식 API라 언제든 깨짐 |
| 공동인증서 비밀번호 자동 입력 | **결정 대기.** PoC 0에서 홈택스 로그인에 필요함을 확인 (인증서 선택창, DreamSecurity 계열). 선택지: ① 자동 입력 (키보드보안 차단 여부 PoC + 인증수단 관리 쟁점) ② 로그인만 세무사가 하고 세션 유지 (홈택스 세션 만료 시간 실측 필요) |
| 반자동 (엑셀 다운로드 + 수동 업로드, 결과만 기록) | **최종 폴백** (§9) |

### 3-2. 로컬 브리지 — 불필요

위하고·홈택스·위택스가 모두 같은 노트북에 있으므로 신고 파일이 기기 밖으로 나가지 않는다. 오전 안의 LAN HTTP·공유폴더·USB 브리지는 **위하고를 다른 기기에서 돌리는 구성으로 되돌아갈 때만** 재검토한다.

### 3-3. 서버 통신·인증

- 노트북 → 서버 HTTPS 폴링 (5초). 서버는 노트북에 접속하지 않는다
- 에이전트 토큰 `X-Agent-Token` (서버에는 SHA-256 해시만, 발급 시 1회 노출, 분실 시 즉시 폐기). 오전 문서의 "JWT + 익스텐션 등록 토큰" 방식은 대체

### 4-1. 전송 (직원) — 등록 게이트

| 게이트 | 상태 |
|--------|------|
| 미승인 급여항목이 있는 거래처 차단 ("입력 확인" = 승인 완료) | 배포됨 |
| 자료 없는 거래처 차단 | 배포됨 |
| 사업자번호 없는 거래처 차단 (수임처 검색 불가) | 배포됨 |
| 같은 신고·거래처에 대기·진행 중 작업이 있으면 차단 | 배포됨 |
| **이번 달 입·퇴사가 있는 거래처는 "위하고 사원등록 완료" 확인 전까지 차단** | 신규 (이지원천의 입·퇴사 변동 데이터로 대상 자동 선별) |
| 반기납부 거래처는 신고 대상 월이 아니면 신고 단계에서 제외 (§4-7) | 신규 |

- 위하고에 올라가는 것은 직원별 급여명세서가 아니라 **22컬럼 급여대장 엑셀**(`payroll_excel.py`)이다. 흐름 안에서는 "급여자료"로 부른다
- 엑셀은 직원 PC에 내려받지 않는다. **노트북이 서버 API로 직접 받는다** (공유폴더·USB 경유는 승인 우회·중복·파일 잔존 문제로 기각)

### 4-2. 위하고 작업 (노트북)

1. 급여대장 엑셀 수신 → `%USERPROFILE%\.easyone-agent\work\` 임시 보관 (처리 후 즉시 삭제)
2. 로그인 상태 확인, 필요 시 노트북에 저장된 전용 아이디로 자동 로그인 (실패 1회 즉시 에이전트 정지 — 계정 잠금 방지)
3. 사업자번호로 수임처 검색 → 결과 정확히 1건 → 화면 상호·사업자번호를 작업 스냅샷과 대조 ((주)/주식회사·공백·하이픈 무시). 어긋나면 중단
4. **사원 존재 확인** — 엑셀의 사원(사원코드·이름)이 위하고 사원 목록에 모두 있는지 확인. 없으면 "위하고 미등록 사원: 홍길동"으로 실패 회신 (직원의 사원등록 누락 대비 2차 안전망). 사원 인적사항은 서버로 가져오지 않는다
5. 급여자료 입력 → 원천세 작업 → 지방세 작업, **단계마다 대조**

| 단계 | 대조 항목 (위하고 화면 vs 이지원천 승인값) | 불일치 시 |
|------|----------------------------------------|----------|
| 급여자료 입력 | 인원, 총지급액, 비과세 | 해당 거래처 중단 |
| 원천세 작업 | 소득세 합계 | 해당 거래처 중단 |
| 지방세 작업 | 지방소득세 합계 | 해당 거래처 중단 |

- 한 거래처가 실패해도 다른 거래처는 계속 진행
- **단계 진행 기록** — 어느 단계까지 끝났는지 작업에 기록하고, 재실행 시 끝난 단계는 건너뛴다 (급여 중복 업로드 방지)
- **서버 전송 범위** — 대조는 노트북에서 하고 서버에는 "일치/불일치"와 **불일치일 때의 차이 항목만** 보낸다 (위하고 원본 값 전체를 서버에 두지 않음, §1-2 ④)
- "원천세 작업"·"지방세 작업"의 범위 (PoC 0 확인, §9-2):

| 작업 | 위하고 T 화면 (화면코드) | 조작 |
|------|------------------------|------|
| 원천세 | 원천징수이행상황신고서 (`SWTA0101`) | [조회] → 대조 → [마감] → "마감 완료!" |
| 원천세 | 거주자사업소득간이지급명세서 (`SWHM0103`) | [마감]. "마감할 데이터가 존재하지 않습니다"는 **건너뛰기** (실패 아님) |
| 원천세 | 원천징수 전자신고 (`SWER0101`) | 수임처 코드도움 → [제작(F4)] → 변환파일 비밀번호 입력 → 파일 제작 |
| 지방세 | 지방소득세특별징수납부서 (`SWTA0112`) | [마감(F3)]. "마감 오류리스트"가 뜨면 **강제마감하지 않고 해당 거래처 중단** (§8-1) |
| 지방세 | 지방소득세특별징수전자신고 (`SWER0109`) | [제작(F4)] → 변환파일 비밀번호 입력 → 파일 제작 |

### 4-3. 완료 알림 (요청 직원)

- 작업의 `requested_by_user_id`로 요청 직원에게 이지원천 알림창
- 거래처별 ✅ 완료 / ⚠️ 불일치(차이 항목) / ❌ 실패(단계·사유 + 수동 처리 안내)
- 로그아웃 상태였던 직원도 놓치지 않도록 다음 접속 시 보여줄 알림 목록 유지

### 4-4. 신고 (세무사 승인 → 홈택스 → 위택스)

- **'신고' 버튼은 세무사(관리자) 권한 전용** — 전송은 직원, 신고는 세무사로 책임 분리
- 신고 대상은 위하고 작업이 ✅인 거래처만 선택 가능
- 원천세·지방소득세 신고 파일은 이지원천이 아니라 **위하고 T [제작]으로 노트북에 생성** (이지원천에는 원천징수이행상황신고서 전자파일 생성 기능이 없음 — `04-excel-outputs.md` Phase 3 이후 항목). 위하고 T에는 **[전송]이 없음** (PoC 0)
  - 파일은 브라우저 다운로드가 아니라 위하고 로컬 모듈이 `C:\Douzone\Wehago\…`에 저장 → Playwright 다운로드 이벤트가 아니라 **저장 폴더 감시**로 수신 (정확한 경로는 실측)
  - **변환파일 비밀번호**(영문 소문자·숫자 8~15자리)는 제작 시 입력하고 홈택스·위택스 제출 시 다시 입력 → 에이전트가 작업마다 생성해 노트북에만 보관, 제출 후 파일과 함께 삭제
- 홈택스: 로그인 (아이디 → 공동인증서 → 세무대리 관리번호, §9-2) → 세금신고 > 원천세 신고 > 일반신고 > **파일변환신고** → [파일선택] → [파일검증하기] → 변환파일 비밀번호 → 검증결과내역(형식·내용검증) → **제출 직전 원천세 합계를 이지원천 값과 대조** → [제출하러 가기] → **일괄접수증 확인 후 성공 처리** → 신고내역 조회(접수증·납부서)
- 위택스: **홈택스 접수가 성공한 거래처만** 신고 > 지방소득세 > 특별징수 > 특별징수신고 > **특별징수 회계파일신고** → [파일첨부] → 파일비밀번호 → [파일변환하기] → 서식검증 및 제출 → 제출결과확인. 홈택스 실패 거래처는 지방세도 건너뛰고 함께 실패 표시
- 홈택스 원천세 신고 후 지방소득세로 이어지는 연계 경로 — PoC 0 영상에서는 위택스에 따로 로그인해 파일을 올림. 연계 경로 유무는 추가 실측

### 4-5. 결과 수집 · 조회 · 사장님 포털 · 납부안내

- 접수증·납부서(국세·지방세) PDF를 노트북이 회수 → 서버 `ClientFilingResult`(`source=RPA`)에 등록 → 이지원천 조회·사장님 포털(`12-owner-portal.md` 보관함) 자동 반영
- PDF가 해당 거래처·귀속월의 것인지 사업자번호로 대조 후 등록
- 납부서에서 **납부세액·전자납부번호·납부기한**을 추출해 칸에 채운다 (포털의 "얼마를 언제까지" 표시에 필수)
- **직원 PC 자동 저장은 불가** (웹은 사용자 PC에 파일을 몰래 쓸 수 없음) → 완료 알림창의 **"접수증·납부서 받기" 버튼** (여러 거래처면 ZIP)
- 이지원천에서 **납부안내 문자** 발송 시 포털 링크 동봉 (30일 수명 링크, `plan.md` 결정 10). 본문은 합계·기한만, 가상계좌 등 상세는 포털에서. 발송 활성화는 `13-messaging-activation.md` 전제
- 납부세액 0원이면 납부서가 없을 수 있음 — "납부서 없음"을 실패로 처리하지 않는다

### 4-6. 사원등록 안내 (자동화 제외)

사원등록(주민번호 등 인적사항, 입사일·퇴사일)은 민감정보이므로 RPA가 건드리지 않는다.
전송 화면에서 대상 거래처에 안내한다:

> "이번 달 입사 2명(홍길동, 김철수)·퇴사 1명이 있습니다. 위하고 T 사원등록에서 직접 입력한 뒤 '사원등록 완료'를 체크하세요. 주민번호 등 인적사항은 자동화하지 않습니다."

### 4-7. 업무 예외

| 예외 | 대응 |
|------|------|
| **반기별 납부 승인 거래처** | 매월 신고 대상 아님. 거래처에 **신고 주기(매월/반기)** 를 두고 대상이 아닌 달은 신고 버튼에서 제외 |
| **연말정산 반영 월**, 중도퇴사자 정산 | 위하고 계산이 급여대장 금액과 달라지는 달. 초기에는 **자동화 제외 → 수동 처리** |
| **수정신고·기한후신고** | 초기 범위 제외, 정기신고만 자동화 |
| **납부세액 0원** | 신고는 하되 납부서 없음 허용 |
| **같은 거래처를 직원이 위하고에서 동시 수정** | 전송 중 거래처를 이지원천 화면에 "위하고 반영 중"으로 표시 |

## §5. 작업 상태 (거래처 × 귀속월)

```
전송대기 → 위하고입력 → 원천세작업 → 지방세작업 → 신고대기(검토)
        → 홈택스신고 → 지방세신고 → 결과수집 → 완료 → (납부안내 발송)
어느 단계든 실패 → 실패(단계·사유) + 수동 처리 안내, 끝난 단계는 재실행하지 않음
```

| `POST /wehago-uploads` | 사용자 | 배포됨 — **입·퇴사 게이트 추가**, 작업 종류 `WEHAGO_MONTHLY`로 확장 |
| `GET /jobs?filing_id=` · `POST /jobs/{id}/cancel` | 사용자 | 배포됨, 유지 (알림·단계 표시용 필드 추가) |
| `POST /agent/claim` | 에이전트 | 배포됨, 유지 (사무소당 1건·재시작·15분 초과 FAILED) |
| `GET /agent/jobs/{id}/payroll-excel` | 에이전트 | 배포됨, **유지** — 오전 A안 (i)의 제거 결정 철회 (노트북이 급여대장을 받는 경로) |
| `POST /agent/jobs/{id}/result` | 에이전트 | 배포됨 — 단계·대조 결과 필드로 확장 |
| `POST /filings` (가칭 — 홈택스·위택스 신고 작업 생성) | **세무사(관리자)** | 신설 |
| `POST /agent/jobs/{id}/filing-result` (접수증·납부서 등록 → `ClientFilingResult`) | 에이전트 | 신설 |

**만들지 않음**: 위하고 신고서 파일 업로드 API, 로그인 정보 저장·조회 API.

- 아이디 로그인만으로 세무대리인 신고 제출까지 되는지, 제출 시 인증서 추가 요구 여부

- 홈택스 원천세 신고 후 지방소득세 연계 신고 경로
- 위택스 세무대리인 신고 가능 여부

**T edge 약관** — 수임처 접점 계획 있으면 추가 검토
