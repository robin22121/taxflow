# 알림톡·SMS 발송 활성화 실행 계획

> 2026-09-08 작성. 현재 알림톡은 `stub`, SMS는 IP 미등록으로 **실발송이 전무한 상태**다.
> [`12-owner-portal.md`](12-owner-portal.md) 사업주 포털의 유일한 진입점이 알림톡 링크이므로,
> 본 문서의 트랙 A·B가 해소되지 않으면 포털 1단계 검증 자체가 불가능하다.

## 1. 현재 상태 진단

| 채널 | 드라이버 코드 | 실배포 설정 | 차단 요인 |
|------|--------------|------------|----------|
| **이메일** | Resend | `EMAIL_PROVIDER=resend` | ✅ 없음 (도메인 verified) |
| **SMS** | `AligoSmsChannel` (`channels/sms.py:47`) — 완성, 90byte SMS/LMS 자동분기 | `SMS_PROVIDER=aligo`, 키 정상 | ✅ 없음 (2026-09-11 IP 등록 → 실발송 성공) |
| **알림톡** | `AligoAlimtalkChannel`(`channels/alimtalk.py:49`), `NhnCloudAlimtalkChannel`(L104) — **구현됨** | `KAKAO_ALIMTALK_PROVIDER=stub` | ⚠️ 카카오 채널·발신프로필·템플릿 미등록 + **코드 구조 불일치**(§3.3) |

> 드라이버는 3종(stub/aligo/nhn_cloud) 모두 있고 팩토리(`get_alimtalk_channel()`, L177)로 분기한다.
> 즉 알림톡은 "미구현"이 아니라 **"계정·템플릿 미등록 + 메시지 조립 방식 불일치"**가 문제다.

**발송 이력은 이미 남는다** — `CollectionEvent`(`backend/app/models/collection.py:43-59`)에
채널·성공여부·에러·msg_id가 매 발송마다 기록되고, `ClientInviteResult`/`ChannelAttempt`로
프론트에 채널별 시도 결과가 그대로 노출된다. 활성화 후 실패 원인 추적에 이 구조를 그대로 쓴다.

### 3.3 ⚠️ 핵심 문제 — 현재 코드는 알림톡으로 전환하면 전부 실패한다

**알림톡은 사전 심사된 템플릿 문구와 본문이 정확히 일치해야 발송된다.**
그런데 현재 코드는 메시지를 **f-string으로 매번 동적 조립**해 `body`(Aligo `message_1`)로 넘긴다.
`template_code`로 쓰이는 `COLLECTION_REQUEST`·`COLLECTION_INVITE`·`CONFIRM_PARSED`·`FOLLOWUP_PAYROLL`
4종은 **카카오에 등록된 코드가 아니라 내부 임의 문자열**이다(별도 레지스트리 없이 4개 파일에 흩어져 있음).

즉 `KAKAO_ALIMTALK_PROVIDER=aligo`로 바꾸는 것만으로는 **전부 반려/실패**한다.

**메시지별 알림톡 적합성 판정**

| 메시지 | 위치 | 내용 성격 | 판정 |
|--------|------|----------|------|
| 자료 요청 / 초대 | `filings.py:186`, `invite.py:83` | 정형 (기간·링크만 변수) | ✅ **알림톡 가능** |
| 신고완료·접수증 안내 (Phase 2) | 미구현 | 정형 (금액·기한·링크) | ✅ **알림톡 가능** |
| 인식결과 확인요청 | `confirmation.py:68-108` | **직원별 동적 목록** | ❌ 알림톡 부적합 |
| 후속질문 | `followup.py:14-53` | **건별 동적 조립** | ❌ 알림톡 부적합 |
| 미등록 거래처 알림 | `webhooks.py:565` | 세무사 앞, 내용 가변 | ❌ SMS 유지 |

동적 목록을 변수 하나에 통째로 넣는 우회가 기술적으로는 되지만,
**"본문 대부분이 변수"인 템플릿은 카카오 심사 반려 사유**다.

### 3.4 해법 — 사업주 포털이 이 문제를 구조적으로 푼다

긴 내용을 메시지에 담으려 하지 말고, **알림톡은 "알림 + 링크"만 보내고 내용은 포털에서 보게 한다.**

```
[before] 알림톡에 직원 목록·금액·확인사항을 전부 담으려 함 → 템플릿화 불가 → 심사 반려
[after]  알림톡: "확인이 필요한 항목이 있습니다. 아래에서 확인해주세요 [버튼]"
         → 포털에서 상세 확인
```

이러면 템플릿이 **정형 3종으로 수렴**하고 심사 통과율이 크게 오른다.
[`12-owner-portal.md`](12-owner-portal.md)의 포털이 단순한 편의 기능이 아니라
**알림톡 운영의 전제**가 되는 셈이다.

### 3.5 등록할 템플릿 (작업 종류별 초안, 2026-09-25 확장)

발신프로필 그룹 공유(§5.4) 여부는 아직 확인 전이다. **일단 사무소별 개별 심사로 시작**하는
전제의 초안이다. 변수는 카카오 규격 `#{변수명}`, 유형은 전부 **기본형**, 버튼은 웹링크(WL).
링크는 전부 포털 상설 링크(`https://www.easyonechon.co.kr/r/...`)라 **도메인 1건만 사전 등록**하면 된다.

**심사 통과 공통 원칙**

- 정보성만. 인사·홍보·"채널 추가" 유도 문구를 넣지 않는다.
- **첫 줄을 변수로 시작하지 않는다.** 사무소별 채널이라 채널명이 곧 사무소명이므로
  기존 초안의 머리표 `[#{사무소명}]`은 알림톡 본문에서 뺀다 (SMS 대체 문구에는 유지 — 발신번호만으로는 누군지 모른다).
- 본문 대부분이 변수면 반려된다. 고정 문구를 충분히 두고 변수는 값만 채운다.
- 금액·주민번호 등 상세는 본문에 늘어놓지 않고 버튼 뒤 포털로 보낸다(§3.4).
- 심사 신청 시 변수 예시값을 함께 낸다. **첫 제출은 반려를 전제로 일정을 잡는다.**

| 코드 | 작업 종류 | 발송 시점 | 버튼 | 코드 구현 | 심사 차수 |
|------|----------|----------|------|----------|----------|
| `COLLECTION_REQUEST` (T1) | 자료 요청 | 수집 세션 시작 | 자료 입력하기 | 있음(`COLLECTION_INVITE`) | **1차** |
| `CONFIRM_PARSED` (T2) | 파싱 결과 확인 요청 | 파싱 후 확인 필요 항목 발생 | 확인하러 가기 | 있음 | **1차** |
| `FILING_NOTICE` (T4) | 세목별 신고안내 | 신고기간 전 일괄 | 자료 보내기 | 있음(§5) | **1차** |
| `PAYMENT_NOTICE` (T5) | 납부(납부서) 안내 | 신고 완료·납부서 확보 후 | 납부서 확인 | 없음(P2) | 2차 |
| `FOLLOWUP_ASK` (T7) | 후속 질문 | 파싱 중 확인 질문 | 답변하기 | 있음(`FOLLOWUP_PAYROLL`) | 2차 |
| `PORTAL_PIN` (T8) | 포털 열람 인증번호 | 사장님이 PIN 요청 | (없음) | 있음 | 2차 |
| `ARREARS_NOTICE` (T6) | 고지·미납 안내 | 홈택스 조회 결과 | (없음) | 없음(P3) | 보류 |

> **1차 3종만 먼저 넣는다.** 온보딩 리드타임(채널·비즈인증 3~4주)에 심사가 얹히므로,
> 수집 흐름이 도는 데 꼭 필요한 T1·T2·T4만 먼저 승인받고 나머지는 SMS로 돌린다.
> **기존 T3(신고 완료)는 T5에 흡수**한다 — 문구가 거의 같아 심사를 두 번 받을 이유가 없고,
> "신고가 완료되었습니다"는 T5 첫 줄로 들어간다.

**T1. 자료 요청** — `COLLECTION_REQUEST`
```
안녕하세요, #{거래처명} 대표님.
#{사무소명}입니다.

#{신고기간} 원천세 신고를 위한 급여 자료를 요청드립니다.

아래 버튼에서 입력하시거나, 평소처럼 담당자에게 보내주셔도 됩니다.

문의: #{사무소연락처}
```
버튼 `자료 입력하기` · 변수 `거래처명` `사무소명` `신고기간` `사무소연락처`

**T2. 파싱 결과 확인 요청** — `CONFIRM_PARSED`
```
안녕하세요, #{거래처명} 대표님.
#{사무소명}입니다.

보내주신 #{신고기간} 자료 중 확인이 필요한 항목이 #{건수}건 있습니다.

아래 버튼에서 확인해 주시면 신고를 진행하겠습니다.

문의: #{사무소연락처}
```
버튼 `확인하러 가기` · 변수 `거래처명` `사무소명` `신고기간` `건수` `사무소연락처`
※ 직원 이름·금액 목록을 본문에 넣지 않는다 (§3.4 — 목록은 포털에서).

**T4. 세목별 신고안내** — `FILING_NOTICE` *(구현 완료)*
```
안녕하세요, #{거래처명} 대표님.
#{사무소명}입니다.

#{세목} 신고기간이 다가와 안내드립니다.

· 신고·납부기한: #{신고기한}
· 준비자료: #{준비자료}

자료를 준비해 보내주시면 신고를 진행하겠습니다.

문의: #{사무소연락처}
```
버튼 `자료 보내기` · 변수 `거래처명` `사무소명` `세목` `신고기한` `준비자료` `사무소연락처`
※ `세목`을 변수로 둬서 부가세·종합소득세·법인세·원천세 4종을 **템플릿 1개로** 처리한다.
   `준비자료`는 서버 레지스트리(`services/message_templates.py`)가 세목별 고정 문구로 채운다.

**T5. 납부(납부서) 안내** — `PAYMENT_NOTICE` *(구 T3 신고완료 흡수)*
```
#{거래처명} 대표님, #{사무소명}입니다.

#{신고기간} #{세목} #{처리구분}되었습니다.

· 납부세액: #{납부세액}원
· 납부기한: #{납부기한}

납부서와 접수증은 아래 버튼에서 확인하실 수 있습니다.

문의: #{사무소연락처}
```
버튼 `납부서 확인` · 변수 `거래처명` `사무소명` `신고기간` `세목` `처리구분` `납부세액` `납부기한` `사무소연락처`
※ `처리구분` 예시값: `신고가 완료` / `납부서가 발행`. 자동화 신고분과 수동 업로드분을 한 템플릿으로 덮는다.
※ 링크 뒤 포털은 PIN 게이트를 거친다 — 납부서 PDF를 알림톡에 첨부할 수 없기 때문이기도 하다.

**T7. 후속 질문** — `FOLLOWUP_ASK`
```
#{거래처명} 대표님, #{사무소명}입니다.

#{신고기간} 자료를 확인하던 중 여쭤볼 내용이 있어 연락드립니다.

확인 요청: #{질문요약}

아래 버튼에서 답변해 주시면 그대로 반영하겠습니다.

문의: #{사무소연락처}
```
버튼 `답변하기` · 변수 `거래처명` `사무소명` `신고기간` `질문요약` `사무소연락처`
※ `질문요약`은 40자 이내로 자른다. 질문 전문을 변수에 밀어 넣으면 "본문 대부분이 변수"로 반려된다.

**T8. 포털 열람 인증번호** — `PORTAL_PIN`
```
#{거래처명} 대표님, #{사무소명}입니다.

자료 열람용 인증번호를 안내드립니다.

· 인증번호: #{인증번호}
· 유효시간: #{유효시간}

인증번호는 본인 확인용입니다. 타인에게 알려주지 마세요.
```
버튼 없음 · 변수 `거래처명` `사무소명` `인증번호` `유효시간`

**T6. 고지·미납 안내** — `ARREARS_NOTICE` *(보류 — 세무대리인 조회 범위 검증 후, §5.1 ④)*
```
#{거래처명} 대표님, #{사무소명}입니다.

국세청 #{세목} #{내역구분} 내역이 확인되어 안내드립니다.

· 금액: #{금액}원
· 납부기한: #{납부기한}

자세한 내용은 담당자에게 문의해 주세요.

문의: #{사무소연락처}
```
※ 체납 사실은 민감정보다. 오발송 시 피해가 가장 크므로 발송 전 거래처·금액 확정 단계를 반드시 둔다.

**SMS 대체 문구 규칙** — 알림톡이 실패하거나 미승인이면 문자로 나간다.
문자 본문은 머리표 `[사무소명]`으로 시작하고, 버튼 대신 링크를 본문에 적는다.
90바이트를 넘으면 LMS로 자동 분기하므로(`channels/sms.py`) 길이 제한을 따로 두지 않는다.

## 4. 실행 순서

```
[지금 즉시]
  A. Aligo 콘솔 IP 등록 (133.186.134.144)        ← 사용자, 5분
       ↓  이것만으로 전 플로우가 문자로 동작
[병렬 착수]
  B1. 카카오 채널 개설 → 비즈 인증 → 발신프로필   ← 사용자, 2~5영업일
  B2. 템플릿 3종 문구 확정 (§3.5)                 ← 문구 설계
       ↓
  B3. 코드 변경 (§3.6) — 템플릿 레지스트리·본문 분리
       ↓
  B4. 템플릿 심사 제출 → 승인                     ← 1~5영업일, 반려 반복 가능
```

알림톡을 1단계의 블로커로 두면 카카오 심사 일정에 제품 검증이 인질로 잡힌다.

## 5. 발송 확장 — 신고안내·납부서·고지서 (2026-09-22 검토)

수집 세션에 묶인 발송(T1~T3) 외에, 사무소가 신고기간마다 거래처 전체에 보내는
**세목 단위 발송**으로 확장한다. 대상 세목은 **부가세·종합소득세·법인세·원천세** 4종.

### 5.1 요청 4종 → 판단

| 요청 | 판단 | 근거 |
|------|------|------|
| ① 원천세 신고안내 | ②에 통합 (세목 기본값 = 원천세) | 별도 기능 불필요 |
| ② 신고안내 (세목 선택) | **P0** | 세목 선택 → 대상 거래처 자동 필터가 핵심. 거래처 세목 필드 신설 필요(§5.3) |
| ③ 납부서 발송 (신고완료분) | **P2** — 기반 절반 존재 | `ClientFilingResult`(납부서 key·세액·가상계좌·전자납부번호·납부기한·게이트3) + 포털 PIN 링크 재사용. 원천세 외 세목은 수동 일괄 업로드 → 사업자번호 자동매칭부터. "자동화 신고완료분"은 [`16-wehago-rpa.md`](16-wehago-rpa.md) 구현 후 |
| ④ 홈택스 미납·고지분 발송 | **P3** — 조회 범위 검증 선행 | 계획 전무. [`17-certificate-issuance.md`](17-certificate-issuance.md) 에이전트의 로그인·거래처 전환 재사용 가능. 세무대리인 권한 조회 범위 실무 확인 필요, 오발송 피해 최대 |

### 5.2 메뉴 — "문자발송" 단일 진입, 채널 선택

- 사이드바 **"문자발송"** 메뉴 신설 (현재는 신고 상세 화면 버튼뿐)
- 발송 화면에서 **문자 / 카톡(알림톡) 선택**. 알림톡 실패 시 SMS 폴백은 기존 체인 사용
- 하위: 발송 · 이력 · 템플릿 · 채널 설정(카카오 채널·발신번호)
- 별도 "알림톡 보내기" 메뉴는 두지 않는다 — 수신자 선택·이력·비용이 중복된다

### 5.3 선행 코드·데이터

- [ ] §3.6 템플릿 레지스트리 (확장 템플릿도 여기에 등록)
- [ ] **수집 세션과 분리된 발송 로그** — 신고안내·납부서는 `CollectionEvent`에 붙일 세션이 없다
- [ ] **예약 발송 스케줄러** — 현재 없음
- [ ] **사무소별 SMS 발신번호** ([`08-action-items.md`](08-action-items.md) §4) — 사무소 채널로 알림톡을 보내면서 폴백 SMS가 이지원천 번호로 나가면 브랜드가 어긋난다
- [ ] `Client` 세목 필드: 부가세 과세유형(일반/간이/면세), 원천세 반기납부 여부, 법인 결산월, 성실신고 대상 여부 — 현재 `is_corporation`만 존재

### 5.4 템플릿 수 억제 (가장 큰 비용)

§3.2 결정상 템플릿 심사는 **사무소별 수동 개별 진행**이라 템플릿 1개 추가 = 사무소 수만큼 심사.
세목·용도별로 쪼개지 말고 범용형으로 수렴한다.

- **T4. 신고안내** — `#{세목}`·`#{신고기한}`·`#{준비자료}` + 버튼 1
- **T5. 납부안내** — `#{세목}`·`#{납부세액}`·`#{납부기한}` + `납부서 확인` 버튼(포털 PIN 링크)
- T6. 고지·미납 안내 — ④ 검증 후

알림톡·MMS 모두 PDF 첨부 불가 → 납부서는 **항상 포털 링크**로 전달.
⚠️ 착수 전 확인: Aligo에서 **발신프로필 그룹 템플릿 공유**(한 번 심사로 여러 사무소 채널 사용) 가능 여부.
가능하면 §3.2 "사무소별 개별 심사"를 재검토한다.

### 5.5 순서

```
P0  템플릿 레지스트리 · 독립 발송 로그 · 사무소별 발신번호 · Client 세목 필드
    · "문자발송" 메뉴 · 세목 선택형 신고안내(SMS)
P1  알림톡 운영 전환(Aligo) + T4·T5 심사 (그룹 공유 여부 먼저 확인)
P2  납부서 발송 — 원천세는 ClientFilingResult 연결, 타 세목은 업로드·매칭
P3  위하고 RPA 납부서 자동 회수 → 홈택스 고지·미납 조회(검증 후)
```
