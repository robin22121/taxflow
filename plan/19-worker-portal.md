# 근로자 포털 — 개요 · 공유 기반

> 2026-09-21 초안. 사업주와 근로자(특히 외국인 노동자)가 **급여명세서 · 고용계약 · 출근·연장근로 기록**을
> 주고받는 화면 묶음의 인덱스. 기능별 상세는 [`20-worker-payslip.md`](20-worker-payslip.md),
> [`21-worker-contract.md`](21-worker-contract.md), [`22-worker-attendance.md`](22-worker-attendance.md)로 분리.
>
> 본 문서는 세 파일이 공통으로 참조하는 **배경·인증·다국어 파이프라인·접근권 매트릭스**만 담는다.

---

## 1. 배경 — 왜 이 기능 묶음인가

세무사 대상 유료 모델은 유지하고, 거래처 사장님 화면([`12-owner-portal.md`](12-owner-portal.md))에 이어
**근로자 화면을 무료 번들**로 얹는다. 사업주 포털이 세무사 수임 영업 무기라면 근로자 포털은 그 화면의
**가치를 증폭시키는 축**이다.

| 사유 | 내용 |
|------|------|
| **법적 요구** | 근로기준법 §17(근로조건 명시)·§48(임금대장·급여명세서 교부, 2021.11 시행). 외국인 근로자는 외국인고용법상 **모국어 표기 근로계약서** 필수 |
| **분쟁 예방** | 미불임금·연장근로 미지급 분쟁의 대부분이 **기록 부재/불일치**에서 발생. 양측이 실시간 대조 가능한 원장이 있으면 감독 대응 리드타임이 며칠→즉시 |
| **외국인 특화** | 산업 현장(제조·건설·농어업) 외국인 노동자는 한국어 명세서·계약서 이해 곤란 → 미지급·부당공제를 인지 못 함. 자국어 번역이 최소 방어선 |
| **세무사 부가가치** | 사업주 포털만으로는 근로자↔사업주 사각지대(근태·연장근로 실측) 해결 못함. 근로자 포털이 데이터의 **또 다른 진입 채널**이 된다 (사업주 신고 → 근로자 대조·이의 → 정정) |
| **채널 락인 강화** | 사장님 + 근로자 양쪽 화면을 세무사 상품에 얹으면 이탈 비용 상승. Autohire/Employa류가 못 하는 "세무사 무료 번들" 포지션 확보 |

**포지션**: 유료 대상은 여전히 세무사. 근로자·사장님은 무료 번들. 근로자 개인정보·임금 데이터는
[`10-privacy-security.md`](10-privacy-security.md) 원칙을 따르되, 근로자 접근권을 **새로운 축**으로 추가한다.

## 2. 기존 결정과의 관계

### 2.1 사업주 포털과의 관계

| 항목 | 사업주 포털 | 근로자 포털 |
|------|------------|------------|
| 사용자 | 거래처 대표(사장님) | 개별 근로자 (외국인 포함) |
| 진입 채널 | 알림톡·SMS(사업주 번호) | 국제 SMS · 알림톡 · QR 오프라인 |
| 주 기능 | 자료 제출 + 결과 확인 | 자신의 **임금·계약·근태 열람 + 이의제기** |
| 대화 | 세무사 카톡으로 이관 | 사업주 카톡으로 이관(세무사 아님) |
| PIN | 대표자 지정 | 근로자 지정 (§4.3) |
| 세무사 접근권 | 세무사 대시보드에서 모두 조회 | 세무사는 "발송·열람·확인" 상태와 이의 통계만. 급여 세부는 이미 사업주 포털/대시보드에 존재 |

### 2.2 데이터 모델 확장 축

기존 `Employee` + `PayrollEntry`([`02-data-model.md`](02-data-model.md))는 그대로 재사용. 근로자 포털은
이 두 개의 **읽기 뷰 + 하위 문서에서 신설하는 5개 모델**로 구성한다.

- `WageAcknowledgment` — [`20-worker-payslip.md`](20-worker-payslip.md)
- `EmploymentContract`, `ContractView` — [`21-worker-contract.md`](21-worker-contract.md)
- `AttendanceRecord`, `OvertimeRequest` — [`22-worker-attendance.md`](22-worker-attendance.md)
- `WorkerAccessToken` — 본 문서 §4

### 2.3 세무사법 리스크와의 관계

근로자에게 노동상담·산업안전 자문을 하지 않는다. 화면은 **기록 열람 + 이의제기 접수**만 한다.
이의제기는 우리가 응대하지 않고 **사업주(또는 사업주가 위임한 세무사)에게 이관**된다.
"입(mouth)을 달지 않는다" 원칙은 [`12-owner-portal.md`](12-owner-portal.md) §2와 동일.

## 4. 인증 · 보안 모델 (공유)

### 4.1 기본 방침 — 사업주 포털 모델 승계

[`12-owner-portal.md`](12-owner-portal.md) §4.3 "상설 링크 + PIN 게이트" 모델을 근로자 단위로 복제.

- 근로자별 **상설 토큰 링크** (30일 자동 갱신)
- **PIN 게이트** 뒤에 금액·계약 원문 노출
- ID/PW 로그인 없음, OTP 없음 (외국인 근로자 대상 UX 마찰 최소화)

### 4.2 링크 배포 — 국제 SMS 우선

외국인 근로자는 카카오톡을 안 쓰는 경우가 많다. 배포 채널 우선순위를 사업주 포털과 다르게 잡는다.

| 순위 | 경로 | 비고 |
|------|------|------|
| 1 | **문자(SMS/LMS)** — 국제문자 지원 필요 | Aligo LMS 재사용 검토, 한계 시 별도 채널 |
| 2 | **알림톡** — 카카오톡 사용자만 | 사업주 포털 인프라 공유 |
| 3 | **사업주가 QR 프린트 → 근로자 스캔** | 오프라인 폴백. 산업 현장에서 유효 |

> **결정 필요(§8 D4)**: 국제 SMS 발송 채널(Twilio·SendGrid SMS 등) 신규 계약 필요 여부.
> Aligo가 현재 어디까지 커버하는지 실측 필요.

### 4.3 PIN 정책

사장님 포털은 대표자 생년월일 지양이었으나([`12-owner-portal.md`](12-owner-portal.md) §4.3.2),
근로자 포털은 **초기값을 근로자 생년월일 뒷자리 6자리**로 시작하고 최초 진입 시 변경을 유도한다.
외국인 근로자는 여권 생년월일을 기억할 확률이 높고, 랜덤 PIN 문자열을 다국어로 안내하는 UX가
사업주 포털보다 훨씬 어렵기 때문이다.

> 이 정책은 §8 결정 후보(D3). 대안: 4자리 수치 PIN + 최초 진입 시 랜덤 배정.

### 4.4 근로자 신원 확인은 사업주로부터 상속

우리는 근로자 신원을 KYC하지 않는다. **사업주가 등록한 근로자 = 우리가 인증하는 근로자**.
[`12-owner-portal.md`](12-owner-portal.md) §4.2 원칙의 근로자 버전.

### 4.5 `WorkerAccessToken` 모델

```
WorkerAccessToken
├── id (PK)
├── employee_id (FK Employee)
├── client_id (FK Client)
├── token (URL-safe, 상설)
├── pin_hash (bcrypt)
├── locale (초기 언어 코드, ko/vi/th/…)
├── expires_at (30일, 진입 시 자동 갱신)
├── last_viewed_at
└── created_at, revoked_at
```

사업주 포털의 `ClientAccessToken`([`12-owner-portal.md`](12-owner-portal.md) §5.3)과 동일 구조,
`employee_id` 스코프로 분리.

### 5.1 렌더링 대상

| 대상 | 처리 |
|------|------|
| UI 텍스트(라벨·버튼) | i18n 리소스 파일 (정적) |
| 급여명세서 항목명 | 고정 번역 사전 (기본급/연장수당/국민연금 등 100여 항목) |

| 이의제기 자유 텍스트 | 근로자 입력 시 원문 저장 + 한국어 번역 저장 (사업주가 읽을 용) |

| 데이터 | 세무사 | 사업주 | 해당 근로자 | 타 근로자 |
|--------|--------|--------|------------|----------|
| 자기 급여명세서 | ✓ | ✓ | ✓ | ✗ |
| 자기 계약서 원본 | ✓ | ✓ | ✓ | ✗ |
| 자기 근태 | ✓ | ✓ | ✓ | ✗ |
| 이의제기 내용 | 요약만 | 전문 | 자기 것 전문 | ✗ |
| 다른 근로자 급여 | ✓ | ✓ | ✗ | ✗ |
| 이의제기 통계(월별 건수) | ✓ | ✓ | ✗ | ✗ |

## 7. 절대 넣지 않을 것 (공유)

| 금지 | 이유 |
|------|------|
| 근로자 상담 채팅·노동청 연결 | 세무사법·노무사법 리스크. 우리는 **기록만** 제공 |
| 급여 계산 근거 상세 설명 | "왜 적죠?" 문의 폭증 → 사업주 부담 증가 → 이탈 |
| 근로자 → 세무사 직접 문의 | §2.1 원칙. 대화는 사업주 카톡으로 이관 |
| 외국인 근로자 신원(여권·비자 번호) 직접 등록 화면 | 개인정보 스코프 확장. 필요 시 사업주 포털의 기존 개별 보안 입력 URL로 분리 |

## 8. 결정 필요 / 논의 사항 (공통 영역)

| 번호 | 항목 | 초안 default | 대안 |
|------|------|-------------|------|
| D1 | 근로자 화면 대화 기능 | 없음 (사업주 카톡 이관) | 사업주 포털과 통합된 알림톡 채널 |
| D2 | PIN 정책 | 생년월일 뒷 6자리 시작, 변경 유도 | 랜덤 4자리 최초 배정 |
| D3 | 국제 SMS 채널 | Aligo 확인 후 결정 | Twilio·SendGrid SMS 별도 계약 |
| D4 | 이의제기 통계 노출 범위 | 세무사·사업주만 | 근로자에게도 자기 이력 노출 |
| D5 | 공용 세무사법 리스크 재검토 | Phase 1.5 착수 전 전문 자문 | 자문 없이 진행 |

기능별 세부 결정 사항은 각 하위 문서 §"결정 필요" 참조.
