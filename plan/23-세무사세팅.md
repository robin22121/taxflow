# 세무사 세팅 — 세무사사무소 서비스 도입 시 기본 세팅

신규 세무사사무소가 이지원천을 도입할 때 **한 번 해 두어야 하는 세팅**을 순서대로 모은 체크리스트다.
자동화 전용 노트북(“이지원”)을 사무소에 따로 설치한다고 가정한다.

상세 설계는 각 영역 문서에 있고, 이 문서는 “무엇을·누가·언제” 하는지만 정리한다.

| 영역 | 상세 문서 |
|------|----------|
| 자동화 노트북·위하고 RPA | [`16-wehago-rpa.md`](16-wehago-rpa.md) §8-2, §9, §12 · [`rpa-agent/README.md`](../rpa-agent/README.md) |
| 문자·알림톡 | [`13-messaging-activation.md`](13-messaging-activation.md) §2, §3.2 · [`08-action-items.md`](08-action-items.md) §4 |
| 계정·권한 | [`14-accounts-permissions.md`](14-accounts-permissions.md) |

## 0. 한눈에 — 순서와 소요 기간

카카오 채널 심사가 가장 오래 걸리므로(3~4주) **계약 직후 제일 먼저 시작**한다. 나머지는 그동안 병행한다.

| 순서 | 항목 | 소요 | 이지원천 담당 | 사무소 담당 |
|------|------|------|--------------|------------|
| 1 | 카카오톡 채널·알림톡 (§3) | 3~4주 (심사 반려 시 더) | 채널 개설·비즈 인증·senderKey·템플릿 심사 대행 | 로고·사업자등록증 사본, 응대 담당자 지정 |
| 2 | 문자 발신번호 (§2) | 1~3영업일 | 알리고에 발신번호 등록 | 사무소 대표번호 명의 확인 |
| 3 | 이지원천 사이트 설정 (§1) | 1~2일 | 사무소 승인·발신번호 입력 | 직원 계정, 거래처·사원·급여 기본값 확인 |
| 4 | 자동화 노트북 설치 (§4) | 반나절 | 설치·설정 대행 (방문 또는 원격) | 노트북 제공, 전용 아이디·인증서 준비 |
| 5 | 수임처별 위하고 세팅 맞추기 (§5) | 수임처 수에 비례 | 누락 목록 뽑기 | 사원·수당·공제 등록 |
| 6 | 시범 운영 (§6) | 1개월 | 모니터링 | 거래처 1~2곳으로 한 달치 진행 |

## 1. 이지원천 사이트 설정

자동화가 맞게 돌려면 **이지원천에 입력한 값이 위하고와 같아야** 한다. 특히 거래처 사업자번호·사원코드·급여 기본값이 어긋나면
에이전트가 멈추거나 금액이 빠진다.

### 1-1. 사무소 (이지원천 서버 관리자)

- [ ] 사무소 가입 승인, 결제기간 입력 (서버 관리자 화면)
- [ ] 사무소 문자 발신번호(`sms_sender`) 입력 — §2의 알리고 등록이 끝난 번호만
- [ ] (알림톡 활성화 후) 사무소 카카오 채널 senderKey 등록 — §3

### 1-2. 사무소 관리자 (설정 화면)

- [ ] 계정 정보 확인 — 아이디는 사업자번호
- [ ] 직원 계정 만들기 — 권한 구조는 `14-accounts-permissions.md`
- [ ] **사무소 인가코드** 확인 — 직원이 카카오톡 이지원천 채널에서 `등록 <코드>`를 입력하면 사무소에 연결된다
- [ ] **자동화 PC 연결**에서 에이전트 토큰 발급 — §4-3에서 노트북 `setup`에 넣는다

> ⏳ 설정 화면의 “자동화 PC 연결” 안내 명령은 지금 증명발급 에이전트(`certificate_agent`)용이다. 위하고 에이전트는 토큰만 받아 `setup`에 입력한다.

### 1-3. 거래처(수임처)별

- [ ] 거래처 등록 — 위하고 T에서 가져오기(`16-wehago-rpa.md` §12)를 쓰면 수임처·사원 기본사항을 한 번에 가져온다
- [ ] **사업자번호가 위하고 수임처와 같을 것** — 에이전트는 사업자번호로 위하고 수임처를 찾고, 상호·사업자번호가 어긋나면 멈춘다
- [ ] 대표자 **휴대폰 번호** — 자료요청·확인요청·신고완료 문자/알림톡을 받는 번호
- [ ] 법인/개인, **원천세 반기납부 여부**, 결산월
- [ ] (사장님이 암호 걸린 엑셀을 보내는 거래처) 첨부파일 비밀번호
- [ ] **급여 기본값** — 식대·자가운전·보육수당 기본 금액, 4대보험 적용 여부, 요율 예외.
      **여기서 금액을 넣은 수당은 그 수임처 위하고에도 등록돼 있어야 한다** (§5-2). 예: 식대 기본값 200,000원인데 위하고에 식대 수당이 없으면 전송 시 멈춘다
- [ ] 세팅이 끝나면 사장님께 초대 발송

### 1-4. 사원별

- [ ] **사원코드가 위하고와 같을 것** — 사원코드가 없거나 다르면 위하고 전송이 막힌다
- [ ] 주민번호, 입사일·퇴사일
- [ ] 부서·직급·직종 (위하고 급여 금액에는 영향 없음)
- [ ] 사업소득자는 업종코드(940100~940929)

## 2. 문자 발송 (알리고)

문자는 **이지원천의 알리고 계정**으로 보낸다 (2026-09-11 실발송 검증 완료). 발신번호는 사무소별로 바꿀 수 있다.

- [ ] **사무소 대표번호를 알리고 발신번호로 등록** — 발신번호 사전등록제에 따라 번호 명의 인증이 필요하다 (알리고 안내에 따라 사무소가 인증 절차에 응한다)
- [ ] 등록된 번호를 이지원천 사무소 발신번호(`sms_sender`)에 입력 — §1-1

> ⏳ **부분 구현**: 사무소 발신번호는 지금 **신고안내 문자에만** 쓰인다 (`api/messages.py`).
> 초대·확인요청·후속질문 문자는 아직 이지원천 기본 번호로 나간다 (`08-action-items.md` §4 “개별 세무사사무소 발신번호로 SMS 발송”).

## 3. 카카오톡 채널·알림톡

알림톡은 **사무소 이름의 카카오톡 채널**로 보낸다 (2026-09-21 결정, `13-messaging-activation.md` §3.2).
채널은 사무소 자산이고, 개설·심사 절차는 이지원천이 대행한다.

| 단계 | 소요 | 이지원천 | 사무소 |
|------|------|---------|--------|
| [ ] 카카오톡 채널 개설 | 즉시 | 사무소명·인사말 세팅 | 로고 제공 |
| [ ] 비즈니스 채널 전환 | 1~3영업일 | 신청 대행 | 사업자등록증 사본 |
| [ ] 발신프로필 등록 → senderKey 발급 | 1~2영업일 | 알리고 파트너 계정으로 대행 | — |
| [ ] 템플릿 3종 심사 (자료요청·확인요청·신고완료) | 1~5영업일, 반려 반복 가능 | 마스터 문구 제출·반려 시 수정 | — |
| [ ] 채널 관리자 권한 이양·응대 교육 | 즉시 | 사무소 직원 카카오 계정 초대, 채널관리자 사용법 안내 | 응대 담당자 지정 |
| [ ] 이지원천 서버에 senderKey 등록 | 즉시 | 암호화 저장 | — |

- 사장님이 채널로 보내는 **답장(인바운드)은 사무소 직원이 카카오톡 채널관리자에서 직접 응대**한다. 이지원천 화면에 통합하지 않는다
- 사무소가 이탈하면 채널은 사무소에 남고, 이지원천은 senderKey를 폐기한다
- 채널 대행 위임은 이용계약서 별도 조항으로 받는다 (법무 검토 필요)

> ⏳ 알림톡 발송은 템플릿 레지스트리·본문 분리 코드 변경 후 켠다 (`13-messaging-activation.md` §3.3·§3.6). 그 전까지는 문자로 전 과정이 돈다.

## 4. 자동화 노트북(“이지원”) 설치

노트북 한 대에 위하고·홈택스·위택스 로그인 정보와 공동인증서가 모이므로 **보안 조건을 먼저 갖춘 뒤** 프로그램을 설치한다.

### 4-1. 계정·인증서 준비 (사무소)

- [ ] **자동화 전용 세무사 아이디** — 위하고 T·홈택스·위택스. 직원이 쓰는 아이디와 따로 만든다 (같은 아이디로 동시에 로그인하면 세션이 끊겨 작업이 실패한다)
- [ ] 전용 아이디로 **모든 수임처에 접근**되는지 위하고 T에서 확인
- [ ] 홈택스 로그인용 **세무법인 공동인증서**와 비밀번호, 세무대리 관리번호·비밀번호
- [ ] 공동인증서 만료일과 갱신 담당자 지정

### 4-2. 노트북 보안 (`16-wehago-rpa.md` §8-2)

- [ ] 자동화 전용 Windows 계정 1개, 로그인 비밀번호 설정, **자동 로그온 끄기**
- [ ] **VeraCrypt 시스템 암호화** (Windows Home 포함, BitLocker 쓰지 않음)
- [ ] 절전·자동 업데이트 재부팅 끄기
- [ ] 사무소 내 보관 장소 지정, 외부 반출 금지
- [ ] 공동인증서는 이 노트북에만 저장 (복사·반출 금지)

### 4-3. 프로그램 설치

- [ ] 크롬, Python 3.12 이상 설치
- [ ] 이지원천 에이전트 설치 (`rpa-agent/README.md` “설치”)
- [ ] 에이전트 전용 크롬 실행 — `scripts/start-chrome.ps1` (원격 디버깅 포트 9222, 전용 프로필). 직원 크롬과 프로필이 분리된다
- [ ] 전용 크롬 창에서 위하고 T·홈택스·위택스에 한 번씩 로그인해 보안 프로그램 설치 안내가 뜨면 설치
- [ ] 사무소 관리자 계정으로 **에이전트 토큰 발급** (토큰은 한 번만 보인다)
- [ ] `python -m easyone_agent setup` — 토큰과 위하고·홈택스·위택스 로그인 정보, 공동인증서 비밀번호를 Windows 자격 증명 관리자에 저장
- [ ] `python -m easyone_agent login-test` — 위하고 로그인만 해 보고 끝낸다 (업로드 없음)
- [ ] Windows 시작 시 크롬·에이전트 자동 실행 등록

> ⏳ **미구현**: 설치 파일 패키징·작업 스케줄러 자동 등록, 에이전트 발급 화면(지금은 API 문서 `/docs`에서 호출). 현재는 이지원천 담당자가 직접 설치한다.

- 비밀번호나 인증서 비밀번호를 바꾸면 `setup`을 다시 실행한다 (틀린 비밀번호로 반복 시도하면 계정이 잠긴다 — 에이전트는 로그인 1회 실패 시 스스로 멈춘다)
- 노트북을 잃어버리거나 교체하면 관리자 계정으로 에이전트 토큰을 폐기한다

## 5. 수임처별 위하고 세팅 맞추기

에이전트는 위하고 급여자료입력의 **엑셀 불러오기**로 급여를 올린다. 이때 위하고는 엑셀 제목과
**같은 이름으로 등록된 항목만 자동 연결**한다 (2026-09-25 실측). 그래서 수임처마다 위하고에
아래 항목이 준비돼 있어야 한다.

### 5-1. 사원

- [ ] 이지원천 사원이 위하고 사원등록에 모두 있을 것
- [ ] **사원코드가 이지원천과 위하고에서 같을 것** — 엑셀의 사원코드로 위하고 사원을 찾는다
- [ ] **보육수당(육아수당) 금액이 있는 사원은 위하고 사원등록에 6세 이하 자녀 정보**를 넣을 것 —
      자녀 정보가 없으면 위하고가 보육수당을 **과세**로 계산한다 (2026-09-25 서도 윤미래 실측 — 자녀 등록 후 재업로드로 비과세 일치 확인).
      에이전트는 저장 후 비과세 합계가 이지원천과 다르면 “대조 불일치”로 알려 준다

사원 등록은 자동화하지 않는다 (`16-wehago-rpa.md` §4-7). 입·퇴사자가 생기면 사무소가 위하고에 먼저 등록한다.

### 5-2. 수당·공제 항목

급여자료입력 → [수당/공제등록]에서 등록한다. 맞추는 기준이 항목마다 다르다.

- **비과세 수당(식대·자가운전·보육수당)은 비과세 코드만 맞으면 된다.** 이름은 사무소 마음대로 붙여도 된다 (“육아수당”, “식대비” 등)
- **나머지 수당·공제는 이지원천 엑셀 제목과 같은 이름**이어야 한다

| 구분 | 이지원천 엑셀 제목 | 위하고에서 맞출 것 | 비고 |
|------|------------------|------------------|------|
| 수당 | 기본급, 상여 | 이름 | 대부분 기본 등록돼 있음 |
| 수당 (비과세) | 식대 | 비과세 코드 **P01** | 식사대 월 20만원 이하 |
| 수당 (비과세) | 자가운전 | 비과세 코드 **H03** | 자가운전보조금 |
| 수당 (비과세) | 보육수당 | 비과세 코드 **Q02** | 출산·6세 이하 자녀 보육 월 20만원 이내. 이지원천 화면의 “육아수당”이 이것이다 — 위하고 “육아/산전후휴가(E01, 육아휴직급여)”와 다르다 |
| 공제 | 국민연금, 건강보험, 고용보험, 장기요양보험료, 소득세, 지방소득세, 학자금상환액 | 이름 | 대부분 기본 등록돼 있음 |
| 공제 | 정산보험료, 월세지원금 | 이름 | 쓰는 수임처만 |

**비과세 수당을 비과세 코드로 맞추는 방식** (2026-09-25 구현)

1. 에이전트가 급여자료입력 화면을 조회하면 가운데 [급여항목] 칸에 그 수임처의 수당 목록이 뜬다.
   에이전트는 이 목록에서 수당명과 비과세 코드를 읽는다. 화면에 이미 받아 둔 값을 읽을 뿐이고 위하고 서버에 따로 요청하지 않는다
2. 노트북에 받은 급여 엑셀의 식대·자가운전·보육수당 열 제목을, 같은 비과세 코드로 등록된 위하고 수당명으로 바꾼다.
   예: 서도는 보육수당(Q02)을 “육아수당”으로 등록해 두었으므로 J열 제목 “보육수당” → “육아수당”
3. 제목을 바꾼 사본을 [엑셀 불러오기]로 올리면 위하고가 이름으로 자동 연결한다. 사본은 올린 직후 지운다

이름은 수임처마다 제각각이지만 비과세 코드는 신고서에 들어가는 값이라 더 믿을 수 있다. 과세 수당(기본급·상여 등)에는 비과세 코드가 없어서 이 방식을 쓸 수 없고 이름으로 맞춘다.

- **금액이 있는 항목만 필수**다. 그 수임처가 식대를 주지 않으면 식대는 등록하지 않아도 된다
- 같은 비과세 코드로 수당을 여러 개 등록해 두었으면 목록의 첫 번째 수당으로 들어간다
- 지급액계·공제액계·차인지급액은 위하고가 다시 계산하므로 등록하지 않는다
- 부서·직급·직종은 연결되지 않아도 급여 금액에는 영향이 없다
- 비과세 코드는 수임처 실정에 맞게 세무사가 최종 판단한다 (위 코드는 일반적인 경우)

**누락되면** 에이전트가 [확인]을 누르지 않고 멈춘다. 그대로 올리면 그 금액이 빠진 채 저장되기 때문이다.

| 메시지 | 뜻 | 조치 |
|--------|----|------|
| 위하고 비과세 수당 미등록: 보육수당(Q02) | 금액이 있는데 그 비과세 코드의 수당이 위하고에 없음 | 위하고에 Q02 수당 등록 (이름 자유) |
| 위하고 수당·공제 미등록: 정산보험료 | 금액이 있는데 같은 이름의 항목이 위하고에 없음 | 위하고에 같은 이름으로 등록 |

사무소가 위하고에 항목을 등록한 뒤 다시 전송한다.

### 5-3. 급여자료입력 기본값

- 구분은 기본값 **“2. 급여+상여”** 를 그대로 쓴다
- 지급일은 이지원천 급여 자료의 지급일로 입력한다. 같은 지급일에 이미 급여가 입력돼 있으면 에이전트는 덮어쓰지 않고 멈춘다

> 💡 도입 초기에 수임처 전체를 한 번에 점검하려면, 에이전트의 **점검 모드**(저장하지 않고 매핑까지만 확인)를
> 수임처별로 돌려 누락 목록을 뽑는 방법이 있다. ⏳ 일괄 점검 기능은 아직 없다.

- [ ] 문자·알림톡이 사장님 폰에 사무소 이름으로 도착하는지 확인
- [ ] 문제가 없으면 전 거래처로 확대
