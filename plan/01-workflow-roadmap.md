## 1. 핵심 자동화 로직

### 1.1 원천세 신고 4단계와 자동화 범위

```
[전체 프로세스]
고객 원시데이터 → 신고서 양식 변환 → 더존 SmartA 입력 → 홈택스 전자신고 → 접수증·납부서 자동 발송
       ▲                  ▲                ▲              ▲                  ▲
       │                  │                │              │                  │
   AI 자동수집         AI 표준화      RPA 에이전트       SmartA 내장기능      알림톡·문자 자동전달
   (Phase 1)        (Phase 1)         (Phase 2)        (Phase 2)          (Phase 2~3)
```

### 1.2 통합 워크플로우

```
[0] (최초 1회) 기존 데이터 임포트 — 매칭 엔진의 전제 조건
    ├─ SmartA에서 급여대장 엑셀 내보내기 → TaxFlow에 업로드 (권장)
    ├─ 또는 세무사가 자유 양식 엑셀 직접 작성 → 업로드
    └─ 또는 첫 달은 전원 신규로 시작 → 승인 시 자동 누적
    → 직원 마스터(Employee) + 전월 급여 이력(PayrollEntry) 초기화
    → 2달째부터는 매월 자동 누적되므로 재임포트 불필요
       ↓
[1] 세무사가 대시보드에서 "이번 달 원천세 자료 요청" 버튼 클릭
       ↓
[2] 시스템이 등록된 거래처 100곳에 알림톡 일괄 발송
    (각 거래처별 토큰 URL 포함)
       ↓
[3] 거래처 → 세무사 직원 → 이지원천 전달 (3가지 경로)
    ├─ 경로 A: 세무사 직원이 거래처 카톡 자료를 이지원천 비즈채널로 공유/전달 → AI 파싱 (1순위)
    ├─ 경로 B: 세무사 직원이 거래처 이메일을 이지원천으로 포워딩 → AI 파싱
    └─ 경로 C: 세무사 직원이 대시보드에서 직접 업로드 (엑셀/사진) → AI 파싱 (폴백)
       ↓
[4] AI가 데이터 정형화 + 직원 매칭
    - 이름·금액 추출
    - 기존 직원 DB와 매칭 (전월 데이터 기반)
    - 신규 의심자 → 후속 질문 자동 발송
    - "저번달과 똑같아요" 같은 상대 표현 처리
       ↓
[5] 세무사 대시보드에서 검증·승인
    - 거래처별 상태 표시 (수신완료/미수신/검증필요)
    - 이상치 자동 하이라이트 (전월 대비 급증 등)
    - 화면 구조: SmartA 급여대장 양식과 동일 (수당 항목별 + 공제 항목별 + 차인지급액)
       ↓
[6] SmartA 급여대장 양식 엑셀 생성
    - 인적사항·수당항목·공제항목·차인지급액 자동 계산
    - SmartA 급여대장 양식 호환 엑셀 (Phase 1: 세무사 수동 업로드)
       ↓
[7] RPA 에이전트가 SmartA에 자동 입력 → 신고서 생성 → 홈택스 전자신고
    - 세무사 PC에 설치된 경량 에이전트(exe)가 SmartA 자동 조작
    - pywinauto 기반 Win32 UI Automation
    - Phase 1에서는 엑셀 다운로드 → 수동 업로드, Phase 2에서 에이전트 자동화
       ↓
[7.5] 급여(임금)명세서 자동 생성 → 수임처 직원에게 카톡/문자 발송
    - [6]에서 만든 데이터로 근로기준법 제48조 양식 자동 생성
    - 수임처 사장님이 할 일 = 0 (세무사가 신고하면 자동 교부)
    - 기존 알림톡 채널 재활용
    (Phase 1 — 번들 피처)
       ↓
[8] 접수증·납부서 자동 회수 → 거래처 자동 전달
    - 에이전트가 SmartA에서 접수증·납부서 PDF 추출
    - 이지원천 서버로 업로드 → 거래처별 알림톡/문자 자동 발송
    - "○월 원천세 신고 완료 | 납부기한: ○월 10일 | 납부금액: ○○원"
    (Phase 2~3)
```

## 2. 단계별 로드맵

### Phase 1: 고객 정보 수집·표준화 (MVP, 0~6개월)

**목표**: 다양한 채널로 들어오는 비정형 데이터를 SmartA 급여대장 양식 엑셀로 변환

**핵심 기능**
- **기존 데이터 임포트 (마스터 초기화)**
  - SmartA 급여대장 엑셀 → 직원 마스터(Employee) + 전월 급여 이력(PayrollEntry) 일괄 등록
  - AI 컬럼 자동 매핑 (SmartA 양식·자유 양식 모두 지원)
  - 주민번호는 암호화 저장, 임포트 결과 미리보기 → 세무사 확인 후 확정
  - 실 서비스 전까지는 리얼리스틱 샘플 데이터로 대체 (→ `05-master-import.md` 참고)
- **다채널 자료 요청 발송** (알림톡 + 초대장 이메일 일괄 발송)
- **다채널 자료 수집 (v3.1 — "세무사 직원이 카톡으로 전달")**
  - **핵심 플로우**: 거래처 → (기존 카톡/전화/이메일) → 세무사 직원 → 이지원천 비즈채널로 공유/전달 → 웹훅 → AI 파싱 → 서버 저장
  - 거래처와 세무사 사무실의 기존 소통 방식 유지 (신뢰 관계·상담 대응)
  - 세무사 직원은 카톡 안에서 "공유하기" 한 번으로 자료 입력 완료 (대시보드 접속 불필요)
  - **거래처 식별 흐름**:
    1. 직원이 거래처명을 명기하여 전송 (예: "하늘식품 김영수 500 박미영 300")
    2. AI가 본문/파일명에서 거래처명 추출 → Client DB 매칭
    3. 매칭 실패 시 → 봇이 "거래처명을 입력해주세요" 되물음
    4. 거래처 확인 완료 후에만 서버에 신고자료 저장
  - **봇 응답 (파싱 결과 즉시 표시)**:
    ```
    ✅ 하늘식품 4월 급여자료 접수 완료

    [기존직원 5명]
    · 박정수 5,400,000원
    · 김미영 4,800,000원
    · 이준호 3,700,000원
    · 최서연 3,300,000원
    · 한동욱 2,700,000원

    [신규 1명]
    · 홍길동 2,000,000원

    [퇴사 1명]
    · 정하늘 (퇴사)

    ⚠️ 확인필요 1건
    · 박정수 급여 +42% 변동 (전월 3,800,000원)

    대시보드: https://이지원천.com/filings/xxx
    ```
  - 세무사 직원이 카톡에서 바로 파싱 결과 검증 → 문제 시 거래처에 즉시 재확인 가능
  - **채널 우선순위**:
    - 1순위 (카카오톡 비즈채널): 세무사 직원이 거래처 자료를 이지원천 채널로 공유/전달 → 오픈빌더 웹훅 (구현 완료)
    - 2순위 (이메일 전달): 세무사 직원이 거래처 이메일을 collect@taxflow.ai로 포워딩 → Inbound Parse (구현 완료)
    - 3순위 (대시보드 직접 업로드): 엑셀/파일을 대시보드에서 직접 업로드 (구현 완료, 폴백)
    - 4순위 (거래처 직접 입력): 알림톡 토큰 URL → 웹폼 직접 입력 (구현 완료, 옵션)
  - 모든 경로는 동일한 `_ingest_message()` 파이프라인으로 합류
  - **폐기**: 거래처 ↔ 이지원천 직접 연결 방식 (상담 대응 불가, 오류 수정 커뮤니케이션 어려움, 신뢰 관계 문제)
  - **폐기**: OAuth 이메일 연동 (보안 거부감, Google 심사 비용, 네이버 API 부재) → research.md 4.6절 참고
- **카톡 메시지 파싱 (AI)**
  - 예: `"김연호 100만원, 박민수 150만원"` → 구조화 JSON
  - `"저번달이랑 똑같아요"` → 전월 데이터 자동 적용
- **엑셀 자동 인식** (컬럼명 다양성 자동 매핑)
- **개별 보안 입력 URL** (주민번호 등 민감정보용)
- **AI 직원 매칭 엔진**
  - 기존 직원 DB와 자동 매칭 (rapidfuzz 85점 이상)
  - 신규/퇴사 의심자 자동 분류
  - 전월 대비 이상치 자동 감지 (1.5배 이상 변동 + 30만원 이상)
  - 후속 질문 자동 발송 (예: "박민수님 신규입사자인가요? 주민번호 입력 부탁드립니다")
  - **전제 조건**: 직원 마스터 + 전월 급여 이력이 DB에 있어야 정상 작동
- **데이터 검증 대시보드** (세무사 최종 승인)
  - 화면 표시 구조: SmartA 급여대장 양식과 동일 (수당 항목별 + 공제 항목별 + 차인지급액)
- **SmartA 급여대장 양식 엑셀 자동 생성**
- **급여(임금)명세서 자동 교부** (번들 피처)
  - 신고 데이터로 근로기준법 제48조 양식 급여명세서 자동 생성
  - 수임처 직원에게 알림톡/문자로 자동 발송 (기존 채널 재활용)
  - 수임처 사장님 추가 작업 없음 — NAHAGO 대비 핵심 차별점
  - 세무사 영업 무기: "저희 사무소에 맡기면 명세서 교부 의무도 자동 해결"
  - 배경: 의무화 3년 경과에도 직장인 23.8% 미수령, 숙박·음식점업 48.5% 미교부
  - 과태료 1차 30만원 → 2차 50만원 → 3차 100만원 (직원 1명당 매월 별도 산정)

**산출물**
- 세무사가 다운로드해서 SmartA에 그대로 업로드 가능한 급여대장 양식 엑셀
- 수임처 직원별 급여(임금)명세서 (PDF/이미지) + 자동 발송

**Phase 1 끝나면 무엇이 가능한가?**
- 고객 응대 시간 80% 절감
- SmartA 입력은 세무사가 엑셀 업로드 한 번으로 끝
- 신고·납부서까지는 SmartA 기존 워크플로우 활용
- **급여명세서 교부 의무 자동 해결** — 수임처에 추가 비용·노력 없이 법 준수

### Phase 2: 더존 SmartA RPA 에이전트 + 신고 후 알림 자동화 (6~12개월)

**목표**: 세무사 PC에 설치된 에이전트가 더존 SmartA에 자동 입력하고, 신고 완료 후 접수증·납부서를 거래처에 자동 발송

#### 2-1. SmartA 자동입력 에이전트

- **세무사 PC에 경량 에이전트 설치** (Python exe, PyInstaller 패키징, ~50MB)
  - 이지원천 서버와 WebSocket/polling으로 통신
  - 이지원천 대시보드에서 "SmartA 입력" 버튼 → 서버 → 에이전트 → SmartA 자동 조작
- **pywinauto 기반 Win32 UI Automation**
  - SmartA는 Windows 데스크톱 앱 (MFC/WinForms 계열)
  - 컨트롤 ID 기반으로 필드 접근 — 이미지 인식보다 안정적
  - 안 잡히는 컨트롤은 PyAutoGUI + OpenCV로 보완 (혼합 방식)
- **자동화 범위**
  - 원천징수이행상황신고서 데이터 입력
  - 신고서 생성 → 검증 → 홈택스 전자신고 트리거
  - 신고 후 접수증·납부서 PDF 추출
- **신고 전 자동 검증**
  - 누락 필드·계산 오류 사전 감지
  - 전월 대비 이상 변동 알림

#### 2-2. 접수증·납부서 자동 발송

- 에이전트가 SmartA에서 접수증·납부서 PDF 추출 → 이지원천 서버 업로드
- 거래처별 알림톡/문자 자동 발송:
  - "○월 원천세 신고가 완료되었습니다"
  - 접수증 PDF 첨부
  - 납부금액·납부기한·가상계좌 안내
- 세무사 대시보드에서 발송 상태 확인 (발송완료/실패/미발송)

#### 2-3. 거래처 직원 마스터 동기화

- 에이전트가 SmartA에서 거래처 직원 명단 주기적 추출
- 이지원천 DB와 자동 동기화 → 신규 직원 매칭 정확도 향상

**왜 "에이전트 방식"인가?**
- SmartA는 Windows 데스크톱 앱 — 웹 RPA 불가, 반드시 로컬에서 조작
- 공동인증서는 클라우드 서버에서 사용 불가 (보안·법적 이슈)
- 블랙피그AI도 동일한 이유로 로컬 PC/미니PC 에이전트 방식 채택

**에이전트 vs 미니PC 전략**
- **초기**: 세무사 PC에 에이전트 설치 (비용 0, 빠른 검증)
- **고객 불만 시**: 미니PC 옵션 추가 (업무 간섭 없음, 야간 일괄 처리 가능, 대당 15~30만원)

**리스크**
- SmartA 버전 업데이트 시 컨트롤 ID 변경 → 에이전트 패치 필요
- 더존 보안 모듈이 자동 조작 차단 가능 → 사전 테스트 필수
- RPA 실행 중 세무사가 SmartA 사용 불가 (미니PC로 해결 가능)

### Phase 3: 입·퇴사 처리 + 확장 자동화 (12~18개월)

- **신규 입사자 등록 흐름**
  - AI 후속 질문 → 주민번호 보안 수집 → SmartA 인적사항 등록 (에이전트)
  - 4대보험 EDI 신고 (사무대행기관 지정 시)
- **퇴사자 처리**
  - 퇴직소득세 계산 → SmartA 입력 (에이전트) → 신고 → 납부서
  - 4대보험 상실 신고
- **각종 지급명세서 자동화**
  - 근로소득 간이지급명세서 (매월)
  - 사업소득 간이지급명세서 (매월)
- **4대 보험 자동 신고 (RPA)** — 자격취득/상실·보수월액 변경을 4insure/공단 EDI에 자동 제출
