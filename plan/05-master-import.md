# 마스터 임포트 + 샘플 데이터 전략

> plan.md §3.6, §3.7 분리본. 매칭 엔진 작동의 전제 조건인 직원 마스터·전월 이력 확보와, 실 서비스 전 검증용 샘플 데이터.

## 1. 마스터 임포트 설계

매칭 엔진이 작동하려면 **직원 마스터 + 전월 급여 이력**이 DB에 있어야 한다.
이 데이터가 없으면 모든 직원이 `NEW_HIRE_SUSPECTED`로 분류되어 실용성이 떨어진다.

### 임포트 소스: SmartA 급여대장 엑셀

SmartA에서 `[급여] → [급여대장] → 엑셀 저장`으로 내보낸 파일이 임포트 원본.
파일명 형식: `{거래처명}-{YYYYMM}.xlsx` (예: `주식회사법인-202604.xlsx`)

하나의 엑셀 파일에 **직원 마스터 + 해당 월 급여 이력**이 모두 포함되어 있다:

| SmartA 컬럼 | TaxFlow 필드 | 용도 |
|-------------|-------------|------|
| 사원코드 | `employee_code` | 직원 식별자 |
| 사원명 | `name` | 매칭 키 |
| 부서 | `department` | 인적사항 |
| 직급 | `position` | 인적사항 |
| 직종 | `job_type` | 인적사항 |
| 기본급 | `base_salary` | 수당 |
| 상여 | `bonus` | 수당 |
| 식대 | `meal_allowance` | 수당 (비과세) |
| 자가운전보조금 | `car_allowance` | 수당 (비과세) |
| 육아수당 | `childcare_allowance` | 수당 (비과세) |
| 지급액계 | `total_payment` | 수당 합계 |
| 국민연금 | `national_pension` | 공제 |
| 건강보험 | `health_insurance` | 공제 |
| 고용보험 | `employment_insurance` | 공제 |
| 장기요양보험료 | `long_term_care` | 공제 |
| 소득세 | `income_tax` | 공제 |
| 지방소득세 | `local_income_tax` | 공제 |
| 학자금상환액 | `student_loan_repayment` | 공제 |
| 연말정산소득세 | `year_end_income_tax` | 공제 |
| 연말정산지방소득세 | `year_end_local_tax` | 공제 |
| 중도정산소득세 | `mid_term_income_tax` | 공제 |
| 중도정산지방소득세 | `mid_term_local_tax` | 공제 |
| 공제액계 | `total_deduction` | 공제 합계 |
| 차인지급액 | `net_payment` | 실수령액 |

### 임포트 흐름

```
[대시보드 → 거래처 관리 → (주)에이상사 → "급여대장 업로드"]
                    │
                    ▼
         SmartA 급여대장 엑셀 업로드 (.xlsx)
                    │
                    ▼
         컬럼 자동 매핑 (SmartA 표준 양식 → DB 필드)
         ├─ 2행 헤더 구조 자동 인식
         ├─ 병합셀 해제 후 컬럼 매칭
         └─ 합계행 자동 제외 (마지막 행)
                    │
                    ▼
         미리보기 화면 (매핑 결과 확인)
         └─ 세무사가 확인 후 "확정" 클릭
                    │
                    ▼
         Employee 테이블 upsert (사원코드 기준 중복 검사)
         + PayrollEntry 테이블 insert (해당 월 급여 데이터)
```

### 임포트 경로 비교

| 경로 | 난이도 | 정확도 | 비고 |
|------|--------|--------|------|
| SmartA 급여대장 엑셀 → 업로드 | 낮음 | 높음 | **권장** — 양식이 정해져 있어 매핑 안정적 |
| 세무사 자유 양식 엑셀 → 업로드 | 낮음 | 중간 | AI 컬럼 매핑으로 커버, 일부 항목 누락 가능 |
| 첫 달 전원 신규 시작 → 자동 누적 | 없음 | 낮음 (첫 달만) | 후속 질문 폭주, 2달째부터 정상화 |

### API 설계

- `POST /clients/{id}/import-payroll` — SmartA 급여대장 엑셀 업로드 → Employee + PayrollEntry 일괄 생성 (구현 완료)
- `GET /clients/{id}/import-preview` — 매핑 결과 미리보기 (확정 전 검토)

## 2. 샘플 데이터 전략 (실 서비스 전)

실제 SmartA 데이터를 확보하기 전까지, **리얼리스틱 샘플 데이터**로 전체 파이프라인을 검증한다.

### 샘플 데이터 구성

| 구성 요소 | 규모 | 내용 |
|----------|------|------|
| 세무사사무소 | 1곳 | 조명신 세무사사무소 |
| 거래처 | 5~10곳 | 업종·규모 다양하게 (음식점, IT회사, 제조업 등) |
| 직원 | 거래처당 3~15명 | 근로/사업/기타/일용 소득구분 혼재 |
| 전월 급여 이력 | 최소 3개월 | 이상치 감지·상대 표현 처리 검증용 |
| 비정형 메시지 샘플 | 50건+ | 카톡 스타일, 엑셀, "전월 동일" 등 다양한 패턴 |

### 샘플 데이터가 커버해야 하는 시나리오

1. **정상 매칭**: 기존 직원, 금액 변동 없음
2. **금액 변동**: 전월 대비 급여 인상/인하 → 이상치 플래그 발생
3. **신규 입사**: 마스터에 없는 이름 → `NEW_HIRE_SUSPECTED` → 후속 질문
4. **퇴사 의심**: 전월 지급 이력 있는데 이번달 누락 → `RESIGNATION_SUSPECTED`
5. **상대 표현**: "저번달이랑 똑같아요", "김연호만 10만원 인상, 나머지 동일"
6. **모호한 입력**: 동명이인, 금액 불명확, 오탈자 → `AMBIGUOUS`
7. **다양한 소득구분**: 근로(WAGE) + 사업(BUSINESS) + 일용(DAILY) 혼재
8. **비과세 포함**: "식대 20만원 포함" → meal_allowance 분리

### 현재 시드 상태

`scripts/seed.py` 확장 완료 (액션 아이템 참고):
- 거래처 7곳, 직원 45명, 4개월 급여 이력
- 8가지 시나리오 커버 (정상 매칭 ~ 모호한 입력)
- 비정형 메시지 샘플 8건 (`test_messages/`)
