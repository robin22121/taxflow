# 세무사 신고 릴레이 (위하고 → 홈택스 → 거래처)

> **상태**: 확장 아이디어 (검증 전, Phase 4+ 후보)
> **분류**: 원천세 이후 수직 확장 — 부가세·종합소득세로 파이프라인 재활용
> **논의 일자**: 2026-09-13

---

## 1. 배경

세무사 사무실 실무에서 **부가세·종합소득세 신고철**은 극한의 반복 작업 기간이다. 신고서 자체는 이미 위하고(더존 클라우드) / 세무사랑 / SMPro 등에서 자동 생성되지만, 그 이후 단계는 여전히 수작업으로 남아 있다:

1. 위하고에서 생성된 신고서 수십~수백 건을 홈택스에 **한 건씩 전송·확정**
2. 신고 완료 후 **접수증·납부서**를 거래처별로 카톡/이메일로 배송
3. 납부 기한·금액을 거래처별로 안내

이지원천은 원천세 영역에서 이 후반 파이프라인(홈택스 전송·접수증 회수·거래처 배송)을 이미 구축하고 있다. 이 자산을 **부가세·종소세**로 그대로 확장하는 것이 릴레이 전략이다.

---

## 2. 포지셔닝

**"위하고를 대체하는 게 아니라 위하고 뒤에 붙는 자동화 레이어"**

- 세무사가 이미 쓰는 신고서 생성 툴(위하고 등)은 그대로 유지 → 도입 저항 최소화
- 이지원천은 신고서 생성 이후 단계만 담당: 홈택스 일괄 전송 + 거래처 배송
- 사무실당 부가세 신고 100~500건 배치 → ROI 즉시 가시화

**차별화 근거**:
- 더존/위하고 자체의 일괄 신고 기능은 있으나 **거래처 커뮤니케이션(접수증·납부서 배송)까지는 안 함**
- 이지원천은 원천세로 이미 거래처 포털·알림톡·AI 파싱 인프라를 보유 — 이 조합을 만드는 회사가 없음

## 3. 기능 개요

```
[위하고에서 신고서 완성 (기존 세무사 워크플로우)]
              ↓
[1] 위하고 데이터 export (파일·CSV·클립보드·스크래핑)
              ↓
[2] 이지원천에서 세무사가 "이 100건 홈택스 전송" 승인 클릭
              ↓
[3] 홈택스 대량 전자신고 API로 배치 전송
              ↓
[4] 접수증·납부서 PDF 자동 회수
              ↓
[5] 거래처별 알림톡·이메일 배송
    "○기 부가세 신고 완료 | 납부기한 · 납부금액 · 접수증 첨부"
              ↓
[6] 거래처 포털에서 접수증·납부서 열람·보관
```

기존 원천세 파이프라인의 [7]~[8] 단계를 그대로 재활용 (`01-workflow-roadmap.md` §1.2 참고).

## 4. 리스크 & 검증 필요 사항

### 4.1 세무사법 (Low — 사실상 blocker 아님)

- 세무대리는 세무사 본인이 하는 것이고, "세무사가 쓰는 SaaS 도구"는 대리 행위가 아님.
- 더존/위하고 자체도 일괄 신고·전자신고 파일 자동 전송을 이미 제공하며 문제된 적 없음.
- **UX 원칙**: 세무사가 로그인·최종 승인·실행 명령을 명확하게 내리는 흐름 유지. 인증서·비번을 저장해두고 스케줄러로 무인 전송하는 극단 케이스만 회피.

### 4.2 홈택스 대량 전자신고 API (High — 실측 필요)

- 세무사용 전자신고 XML 업로드 채널은 존재하나, 신고서 종류별 커버리지·확정 자동화 수준을 실측해야 함.
- 스크래핑은 홈택스 개편 리스크. API 우선, 스크래핑은 폴백.
- **검증 과제**: 부가세·종소세 각각 (1) 대량 업로드 API 스펙 (2) 확정 자동화 가능 여부 (3) 접수증·납부서 PDF 프로그래매틱 회수 가능 여부.

### 4.3 위하고 데이터 export (Medium — 우회 가능)

- Douzone이 자기 고객 이탈 우려로 API 개방을 견제할 가능성.
- 파일 export / CSV / 인쇄 리다이렉트 / 클립보드 스크래핑으로 우회 가능 — 사용자 조작 기반이라 법적 위험 낮음.
- **검증 과제**: 위하고에서 신고서 데이터를 어떤 포맷으로 뽑을 수 있는지, 세무사 사무실이 실제로 어떻게 export하는지 실사.

## 5. 검증 계획 (Discovery)

**세무사 3~5명 인터뷰** (이지원천 기존 고객 우선):

1. 부가세·종소세 신고철에 각 단계별 시간이 얼마나 걸리는지 (신고서 생성 vs 홈택스 전송 vs 거래처 배송)
2. 위하고의 일괄 신고 기능을 이미 쓰고 있는지, 어디서 막히는지
3. 접수증·납부서 거래처 배송을 지금 어떻게 하고 있는지 (수작업 카톡·이메일 vs 자동화 도구 vs 안 함)
4. 홈택스 전송·확정 자동화에 얼마를 낼 의사가 있는지 (신고 건당 · 사무실 월정액)

인터뷰 결과에 따라 Phase 4 상세 스펙 착수 여부 결정.

## 6. 로드맵 위치

- **Phase 4 (18~24개월)** 이후 확장 후보. 현재 로드맵의 "부가세·종합소득세·법인세 보조" 항목을 이 문서로 구체화.
- 선행 조건: 원천세 파이프라인 [7]~[8]단계(SmartA RPA + 접수증 회수 + 거래처 배송)가 프로덕션 안정화된 이후 착수.
- 재활용 가능한 기존 자산: 거래처 포털(`12-owner-portal.md`), 알림톡·SMS 발송(`13-messaging-activation.md`), 개인정보 마스킹(`10-privacy-security.md`).
