## 1. 핵심 자동화 로직

### 1.1 원천세 신고 4단계와 우리의 자동화 범위

```
[전체 프로세스]
고객 원시데이터 → 신고서 양식 변환 → 위하고T 입력 → 홈택스 전자신고 → 접수증·납부서 회수
       ▲                  ▲                ▲              ▲                  ▲
       │                  │                │              │                  │
   AI 자동수집         AI 표준화      엑셀 일괄업로드   위하고T 내장기능       자동 회수·전달
   (Phase 1)        (Phase 1)         (Phase 2)        (Phase 2)          (Phase 3)
```

### 1.2 통합 워크플로우

```
[0] (최초 1회) 기존 데이터 임포트 — 매칭 엔진의 전제 조건
    ├─ 위하고T에서 인적사항 엑셀 내보내기 → TaxFlow에 업로드 (권장)
    ├─ 또는 세무사가 자유 양식 엑셀 직접 작성 → 업로드
    └─ 또는 첫 달은 전원 신규로 시작 → 승인 시 자동 누적
    → 직원 마스터(Employee) + 전월 급여 이력(PayrollEntry) 초기화
    → 2달째부터는 매월 자동 누적되므로 재임포트 불필요
       ↓
[1] 세무사가 대시보드에서 "이번 달 원천세 자료 요청" 버튼 클릭
       ↓
[2] 시스템이 등록된 거래처 100곳에 알림톡 일괄 발송
    (각 거래처별 토큰 URL 포함)
       ↓
[3] 거래처 응답 (3가지 경로)
    ├─ 경로 A: URL 클릭 → 보안 폼에 입력
    ├─ 경로 B: 카톡으로 답장 ("김연호 100, 조명신 120") → AI 파싱
    └─ 경로 C: 엑셀/사진 업로드 → AI 파싱
       ↓
[4] AI가 데이터 정형화 + 직원 매칭
    - 이름·금액 추출
    - 기존 직원 DB와 매칭 (전월 데이터 기반)
    - 신규 의심자 → 후속 질문 자동 발송
    - "저번달과 똑같아요" 같은 상대 표현 처리
       ↓
[5] 세무사 대시보드에서 검증·승인
    - 거래처별 상태 표시 (수신완료/미수신/검증필요)
    - 이상치 자동 하이라이트 (전월 대비 급증 등)
       ↓
[6] 위하고T 표준 엑셀 자동 생성
    - 인적사항·지급액·소득구분코드·세액 자동 계산
    - 위하고T [원천세 신고 → 일괄등록] 양식 100% 호환
       ↓
[7] 세무사가 위하고T에 업로드 → 검증 → 홈택스 전자신고
    (Phase 2에서는 이 부분도 반자동화)
       ↓
[8] 접수증·납부서 자동 회수 → 거래처 자동 전달
    (Phase 3)
```

## 2. 단계별 로드맵

### Phase 1: 고객 정보 수집·표준화 (MVP, 0~6개월)

**목표**: 다양한 채널로 들어오는 비정형 데이터를 위하고T 일괄 업로드용 표준 엑셀로 변환

**핵심 기능**
- **기존 데이터 임포트 (마스터 초기화)**
  - 위하고T 인적사항 엑셀 → 직원 마스터(Employee) 일괄 등록
  - 위하고T 전월 신고 엑셀 → 전월 급여 이력(PayrollEntry) 초기화
  - AI 컬럼 자동 매핑 (위하고T 양식·자유 양식 모두 지원)
  - 주민번호는 암호화 저장, 임포트 결과 미리보기 → 세무사 확인 후 확정
  - 실 서비스 전까지는 리얼리스틱 샘플 데이터로 대체 (→ 3.5절 참고)
- **다채널 자료 요청 발송** (알림톡 + 초대장 이메일 일괄 발송)
- **다채널 자료 수집 (v2.1 — "거래처가 우리에게 보내게 만든다")**
  - 1순위 (카카오톡): 알림톡 발송 → 거래처가 비즈채널에서 카톡으로 답장/파일 첨부 → 오픈빌더 웹훅 → 자동 수집 (웹훅 구현 완료)
  - 2순위 (전용 이메일 초대장): 세무사 명의로 안내 메일 발송 ("이 주소로 보내주세요: collect+거래처@taxflow.ai") → 거래처가 회신/발송 → SendGrid Inbound Parse → 자동 수집 (웹훅 구현 완료)
  - 3순위 (자동 전달): 세무사 메일함에서 필터 규칙 1회 설정 → 원천세 관련 메일 자동 전달 → 동일 파이프라인 (Gmail/네이버/Outlook별 가이드 제공)
  - 4순위 (URL 입력폼): 알림톡/이메일에 토큰 URL 포함 → 거래처가 웹폼에 직접 입력 (구현 완료, 범용 폴백)
  - 모든 경로는 동일한 `_ingest_message()` 파이프라인으로 합류
  - **폐기**: OAuth 이메일 연동 (보안 거부감, Google 심사 비용, 네이버 API 부재) → research.md 4.6절 참고
- **카톡 메시지 파싱 (AI)**
  - 예: `"김연호 100만원, 박민수 150만원"` → 구조화 JSON
  - `"저번달이랑 똑같아요"` → 전월 데이터 자동 적용
- **음성 통화 자동 텍스트 변환** + AI 파싱
- **엑셀 자동 인식** (컬럼명 다양성 자동 매핑)
- **개별 보안 입력 URL** (주민번호 등 민감정보용)
- **AI 직원 매칭 엔진**
  - 기존 직원 DB와 자동 매칭 (rapidfuzz 85점 이상)
  - 신규/퇴사 의심자 자동 분류
  - 전월 대비 이상치 자동 감지 (1.5배 이상 변동 + 30만원 이상)
  - 후속 질문 자동 발송 (예: "박민수님 신규입사자인가요? 주민번호 입력 부탁드립니다")
  - **전제 조건**: 직원 마스터 + 전월 급여 이력이 DB에 있어야 정상 작동
- **데이터 검증 대시보드** (세무사 최종 승인)
- **위하고T 일괄등록용 표준 엑셀 자동 생성**

**산출물**: 세무사가 다운로드해서 위하고T에 그대로 업로드 가능한 표준 엑셀

**Phase 1 끝나면 무엇이 가능한가?**
- 고객 응대 시간 80% 절감
- 위하고T 입력은 세무사가 엑셀 업로드 한 번으로 끝
- 신고·납부서까지는 위하고T 기존 워크플로우 활용

### Phase 2: 위하고T 업로드·신고 반자동화 (6~12개월)

**목표**: Phase 1 산출물을 위하고T에 업로드하고 신고까지 이어주는 흐름 자동화

**핵심 기능**
- **위하고T 엑셀 자동 업로드 어시스턴트**
  - 세무사 PC에 경량 에이전트 설치 (브라우저 확장 또는 데스크톱 앱)
  - 위하고T [일괄등록] 화면에서 "TaxFlow에서 가져오기" 버튼 클릭
  - 표준 엑셀 자동 다운로드·업로드·검증
- **신고 전 자동 검증**
  - 더존 위하고T 양식 규격 검증
  - 누락 필드·계산 오류 사전 감지
  - 전월 대비 이상 변동 알림
- **홈택스 전자신고 트리거**
  - 위하고T 내장 신고 기능 활용 (공동인증서는 세무사 PC 로컬에서)
  - 신고 진행 상태 실시간 추적
- **거래처 직원 마스터 동기화**
  - 위하고T에서 거래처 직원 명단 주기적 가져오기
  - 신규 직원 매칭 정확도 향상

**왜 "에이전트 방식"인가?**
- 공동인증서는 클라우드 서버에서 사용 불가 (보안·법적 이슈)
- 위하고T 로그인은 세무사 PC에서 진행해야 자연스러움
- 블랙피그AI도 동일한 이유로 로컬 PC 에이전트 방식 채택

## 3. Phase 1 MVP 상세 설계

### 3.1 핵심 데이터 모델 (개념도)

```
세무사사무소
   │
   └── 거래처 (Client)
         │  ├── 사업자번호, 법인/개인 구분 (원천징수이행상황신고서 A01/A02 분류용)
         │
         ├── 직원/소득자 마스터 (Employee)
         │     ├── 이름, 주민번호(암호화), 입사일, 퇴사일
         │     ├── 위하고T 직원ID (동기화용)
         │     └── 사업소득 업종코드 (940100~940929, 사업소득자인 경우)
         │
         ├── 사업소득 업종코드 마스터 (BusinessTypeCode) [참조 테이블]
         │     ├── 코드 (940100, 940302, 940906 등 40종)
         │     ├── 종목명 (저술가, 배우, 보험설계사 등)
         │     └── 기본 세율 (3% / 20% / 5%)
         │
         └── 월별 신고 (MonthlyFiling)
               │
               ├── 수집 세션 (CollectionSession)
               │     ├── 발송 알림톡 기록
               │     ├── 응답 수신 로그 (카톡/통화/엑셀)
               │     └── AI 파싱 결과
               │
               ├── 직원별 인건비 항목 (PayrollEntry)
               │     ├── 직원 매칭 결과 (MATCHED / NEW / RESIGNED / AMBIGUOUS)
               │     ├── 소득구분 (WAGE/BUSINESS/OTHER/DAILY/RETIREMENT)
               │     ├── 국세청 A코드 (A01~A99, 위하고T/홈택스 신고서용)
               │     ├── 사업소득 업종코드 (BUSINESS인 경우)
               │     ├── 급여/상여 분리 (근로소득 간이지급명세서용)
               │     ├── 비과세소득 세분류
               │     └── 검증 상태
               │
               └── 출력 양식 (OutputReport)
                     ├── 위하고T 일괄등록용 엑셀 (Phase 1)
                     ├── 간이지급명세서 — 근로소득 (Phase 1)
                     ├── 간이지급명세서 — 사업소득 (Phase 1)
                     ├── 간이지급명세서 — 기타소득 (Phase 3)
                     ├── 일용근로소득 지급명세서 (Phase 3)
                     └── 원천징수이행상황신고서 (Phase 2~3)
```

> **v2.1 변경**: 국세청 공식 서식 분석(research.md 3.4절) 결과를 반영.
> Client에 법인/개인 구분, Employee에 사업소득 업종코드, PayrollEntry에 A코드·급여/상여 분리 등 추가.
> 출력 양식도 위하고T 엑셀 1종에서 간이지급명세서 4종 + 원천징수이행상황신고서까지 확장.

### 3.2 AI 파싱 핵심 로직 (의사 코드)

```python
async def parse_payroll_message(
    raw_text: str,
    client_id: str,
    previous_month_data: dict,
    employee_master: list[Employee]
) -> PayrollParsingResult:
    """
    카톡/이메일 텍스트 → 구조화된 인건비 데이터 + 매칭 결과
    """
    prompt = f"""
    아래는 세무사 거래처가 보낸 이번 달 인건비 자료입니다.

    [거래처 직원 마스터]
    {employee_master}

    [이전 달 데이터]
    {previous_month_data}

    [이번 달 메시지]
    {raw_text}

    다음 JSON 형식으로 반환:
    {{
      "matched_employees": [
        {{"name": str, "employee_id": str, "amount": int,
          "change_from_prev": int, "change_reason": str | null}}
      ],
      "new_hire_suspected": [
        {{"name": str, "amount": int, "needs_confirmation": true}}
      ],
      "resignation_suspected": [
        {{"employee_id": str, "name": str, "reason": "이번달 누락"}}
      ],
      "ambiguous_items": [
        {{"raw_text": str, "issue": str}}
      ],
      "relative_references": [
        {{"text": "저번달과 동일", "applied": true}}
      ]
    }}
    """
    response = await claude_client.messages.create(
        model="claude-sonnet-4-5",
        messages=[{"role": "user", "content": prompt}]
    )
    return validate_and_parse(response)
```

### 3.3 위하고T 표준 엑셀 생성 (의사 코드)

위하고T의 [원천세 신고 → 일괄등록] 양식에 맞춘 컬럼 구성:

```python
# 위하고T 일괄등록용 표준 컬럼 (예시)
WEHAGO_COLUMNS = [
    "사번", "성명", "주민등록번호", "소득구분코드",
    "지급년월", "총지급액", "비과세소득", "과세소득",
    "소득세", "지방소득세", "원천징수일자"
]

def generate_wehago_excel(
    payroll_entries: list[PayrollEntry],
    period: str
) -> bytes:
    """
    AI가 정형화한 데이터를 위하고T 표준 엑셀로 변환
    - 소득세·지방소득세 자동 계산
    - 소득구분코드 자동 매핑 (근로/사업/기타 등)
    - 위하고T 양식 100% 호환
    """
    workbook = openpyxl.Workbook()
    ws = workbook.active
    ws.append(WEHAGO_COLUMNS)

    for entry in payroll_entries:
        tax = calculate_withholding_tax(entry)
        ws.append([
            entry.employee_code,
            entry.name,
            decrypt_rrn(entry.rrn_encrypted),
            map_income_type_code(entry.income_type),
            period,
            entry.total_amount,
            entry.non_taxable,
            entry.taxable,
            tax.income_tax,
            tax.local_tax,
            entry.payment_date
        ])

    return save_to_bytes(workbook)
```

### 3.4 후속 질문 자동 발송

신규 의심자가 감지되면 한 번에 묶어서 발송:

### 3.5 출력 양식 다양화 설계 (국세청 서식 기반)

> 국세청 공식 서식 분석 결과(research.md 3.4절)에 따라, 위하고T 엑셀 1종 외에 간이지급명세서 등 추가 출력이 필요.

#### Phase 1에서 생성하는 출력물

**1. 위하고T 일괄등록용 엑셀** (기존, `wehago_excel.py`)
- 위하고T `[원천세 신고 → 일괄등록]` 양식 호환
- 모든 소득구분 통합 (WAGE, BUSINESS, DAILY 등)

**2. 간이지급명세서 (근로소득)** — 별지 제24호의4서식(1)
- 대상: `income_type=WAGE` 항목
- 주요 컬럼: 귀속연월, 성명, 주민등록번호, 근무기간, 급여, 상여, 비과세, 소득세, 지방소득세
- **컬럼 보강 필요**: 현재 PayrollEntry에 급여/상여 분리가 없음 → `salary_amount`, `bonus_amount` 추가 또는 총지급액 단일 컬럼으로 간소화

**3. 간이지급명세서 (거주자의 사업소득)** — 별지 제24호의4서식(2)
- 대상: `income_type=BUSINESS` 항목
- 주요 컬럼: 귀속연월, **업종코드**, 성명, 주민등록번호, 지급액, 세율(3%), 소득세, 지방소득세
- **업종코드 40종** 마스터 테이블 내장 필요 → Employee 또는 PayrollEntry에 `business_type_code` 필드

#### Phase 3 이후 추가 출력물

**4. 간이지급명세서 (기타소득)** — 소득종류, 필요경비율 적용 필요
**5. 일용근로소득 지급명세서** — 일용직 근무일수·일일비과세(15만원) 처리
**6. 원천징수이행상황신고서** — A코드별 합산, 위하고T가 자동 생성하므로 참고용

#### 소득구분 코드 매핑 테이블

현재 `IncomeType` enum과 국세청 A코드, 위하고T 코드 간 매핑:

| TaxFlow IncomeType | 국세청 A코드 | 위하고T 코드 | 세율 | 간이지급명세서 |
|---------------------|------------|------------|------|-------------|
| WAGE | A01 (법인) / A02 (개인) | 근로 | 간이세액표 | 근로소득용 |
| DAILY | A03 | 일용근로 | 6% (15만원 초과분) | 일용근로소득용 |
| BUSINESS | A25 | 사업 | 3% (기본) | 사업소득용 |
| OTHER | A42 | 기타 | 20% (기본) | 기타소득용 |
| RETIREMENT | A22 | 퇴직 | 퇴직소득세 테이블 | 별도 |

> **v2.1 NOTE**: Client에 법인/개인 구분을 추가하면 WAGE → A01/A02 자동 분류 가능.
> Phase 1에서는 간소화하여 WAGE=A02(개인)로 기본 설정, 법인 거래처만 A01 매핑.

### 3.6 마스터 임포트 설계

매칭 엔진이 작동하려면 **직원 마스터 + 전월 급여 이력**이 DB에 있어야 한다.
이 데이터가 없으면 모든 직원이 `NEW_HIRE_SUSPECTED`로 분류되어 실용성이 떨어진다.

#### 임포트 대상 데이터

**A. 인적사항 마스터 (위하고T → Employee 테이블)**

위하고T `[원천세] → [인적사항관리] → 엑셀 내보내기` 기준:

| 위하고T 컬럼 | TaxFlow 필드 | 비고 |
|-------------|-------------|------|
| 사번 | `employee_code` | 위하고T 내부 식별자 |
| 성명 | `name` | 매칭 키 |
| 주민등록번호 | `rrn_encrypted` | AES-256-GCM 암호화 저장 |
| 입사일 | `hired_at` | |
| 퇴사일 | `resigned_at` | 값이 있으면 `status=RESIGNED` |
| 소득구분 | `income_type` 매핑 참조 | WAGE/BUSINESS/OTHER/DAILY |

**B. 전월 급여 이력 (위하고T → PayrollEntry 테이블)**

위하고T `[원천세 신고] → [원천징수이행상황신고서] → 엑셀 내보내기` 기준:

| 위하고T 컬럼 | TaxFlow 필드 |
|-------------|-------------|
| 사번 | `employee_code` → `employee_id` 매핑 |
| 총지급액 | `total_amount` |
| 비과세소득 | `non_taxable` |
| 소득세 | `income_tax` |
| 지방소득세 | `local_tax` |
| 지급년월 | `period` → MonthlyFiling 매핑 |

#### 임포트 흐름

```
[대시보드 → 거래처 관리 → (주)에이상사 → "직원 마스터 업로드"]
                    │
                    ▼
         엑셀/CSV 업로드 (위하고T 양식 or 자유 양식)
                    │
                    ▼
         AI 컬럼 자동 매핑 (Claude)
         ├─ "사번" → employee_code
         ├─ "성명" / "이름" → name
         ├─ "주민등록번호" / "주민번호" → rrn_encrypted
         ├─ "입사일" / "입사년월일" → hired_at
         └─ "소득구분" / "소득종류" → income_type
                    │
                    ▼
         미리보기 화면 (매핑 결과 확인)
         └─ 세무사가 확인 후 "확정" 클릭
                    │
                    ▼
         Employee 테이블 일괄 upsert
         (중복 검사: client_id + name + rrn_last4)
```

#### 임포트 경로 비교

| 경로 | 난이도 | 정확도 | 비고 |
|------|--------|--------|------|
| 위하고T 엑셀 내보내기 → 업로드 | 낮음 | 높음 | **권장** — 양식이 정해져 있어 매핑 안정적 |
| 세무사 자유 양식 엑셀 → 업로드 | 낮음 | 중간 | AI 컬럼 매핑으로 커버, 주민번호 누락 가능 |
| 첫 달 전원 신규 시작 → 자동 누적 | 없음 | 낮음 (첫 달만) | 후속 질문 폭주, 2달째부터 정상화 |

#### API 설계 (예정)

- `POST /clients/{id}/import-employees` — 엑셀 업로드 → Employee 일괄 생성
- `POST /clients/{id}/import-payroll` — 전월 급여 엑셀 → PayrollEntry 초기 데이터 생성
- `GET /clients/{id}/import-preview` — 매핑 결과 미리보기 (확정 전 검토)

### 3.7 샘플 데이터 전략 (실 서비스 전)

실제 위하고T 데이터를 확보하기 전까지, **리얼리스틱 샘플 데이터**로 전체 파이프라인을 검증한다.

#### 샘플 데이터 구성

| 구성 요소 | 규모 | 내용 |
|----------|------|------|
| 세무사사무소 | 1곳 | 조명신 세무사사무소 |
| 거래처 | 5~10곳 | 업종·규모 다양하게 (음식점, IT회사, 제조업 등) |
| 직원 | 거래처당 3~15명 | 근로/사업/기타/일용 소득구분 혼재 |
| 전월 급여 이력 | 최소 3개월 | 이상치 감지·상대 표현 처리 검증용 |
| 비정형 메시지 샘플 | 50건+ | 카톡 스타일, 엑셀, "전월 동일" 등 다양한 패턴 |

#### 샘플 데이터가 커버해야 하는 시나리오

1. **정상 매칭**: 기존 직원, 금액 변동 없음
2. **금액 변동**: 전월 대비 급여 인상/인하 → 이상치 플래그 발생
3. **신규 입사**: 마스터에 없는 이름 → `NEW_HIRE_SUSPECTED` → 후속 질문
4. **퇴사 의심**: 전월 지급 이력 있는데 이번달 누락 → `RESIGNATION_SUSPECTED`
5. **상대 표현**: "저번달이랑 똑같아요", "김연호만 10만원 인상, 나머지 동일"
6. **모호한 입력**: 동명이인, 금액 불명확, 오탈자 → `AMBIGUOUS`
7. **다양한 소득구분**: 근로(WAGE) + 사업(BUSINESS) + 일용(DAILY) 혼재
8. **비과세 포함**: "식대 20만원 포함" → non_taxable 분리

#### 시드 스크립트 확장 계획

현재 `scripts/seed.py`는 거래처 3곳 · 직원 9명의 최소 데이터만 생성.
→ 위 시나리오를 모두 커버하는 **확장 시드**로 교체:
- 거래처별 직원 수·소득구분 다양화
- 3개월치 PayrollEntry 이력 생성 (전월 비교용)
- 비정형 메시지 샘플 세트 (`test_messages/` 디렉터리)
