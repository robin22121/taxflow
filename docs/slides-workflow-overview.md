# 이지원천 (TaxFlow)

## 세무사무실을 위한 원천세 업무 자동화

<br/>

**한 줄 요약** — 거래처가 카톡으로 보낸 급여자료를 AI가 정리하고, 자동화 전용 노트북 **이지원**(지원이)이 위하고 T·홈택스·위택스까지 신고를 대신 눌러주는 SaaS.

<span class="muted">2026-09-18 · 동업자 브리핑용</span>

---

## 오늘 이야기할 것

1. 왜 만드나 — 원천세 업무의 병목
2. 이지원천이 하는 일 — 8단계 워크플로우
3. Phase 1~4 로드맵
4. 차별화 포인트
5. **[신규]** 알리고 문자 발송 구조 변경 + 부가통신 등록 이슈

---

## 1. 왜 만드나 — 지금의 병목

| 단계 | 지금 | 문제 |
|------|------|------|
| 자료 수집 | 카톡·전화·이메일·엑셀 뒤섞임 | 매달 반복, 사람이 정리 |
| 급여 정리 | SmartA/위하고에 손입력 | 수백 명 × 100 거래처 |
| 신고 | 홈택스·위택스 클릭 반복 | 마감 3일 지옥 |
| 사후 | 접수증·납부서 개별 카톡 발송 | 놓치면 컴플레인 |

<div class="callout">

**핵심**: 블랙피그·혜움도 못 푼 **1단계 (거래처와의 소통·자료 수집)** 를 AI로 자동화한다.

</div>

---

## 2. 이지원천이 하는 일 — 전체 그림

```
고객 원시데이터 ──► 급여 표준화·승인 ──► 위하고 T 입력 ──► 홈택스·위택스 신고 ──► 접수증·납부서 발송
       ▲                  ▲                  ▲                  ▲                     ▲
       │                  │                  │                  │                     │
   AI 자동수집        AI 표준화       이지원(지원이)       이지원(지원이)         포털·알림톡·문자
   (Phase 1)         (Phase 1)          (Phase 2)            (Phase 2)           (Phase 2~3)
```

<div class="small muted">

**이지원** = 사무소에 두는 자동화 전용 노트북 이름. 애칭은 **지원이**. 위하고·홈택스·위택스 클릭을 대신 눌러준다.

</div>

<br/>

**세무사·직원의 클릭 수를 90% 이상 줄이는 것이 목표**

## [0] 최초 1회 — 직원 마스터 초기화

<div class="ok">

매칭 엔진이 돌려면 "전월 데이터"가 필요하다. 첫 도입 시 딱 한 번 세팅.

</div>

- **선택 A** — SmartA에서 급여대장 엑셀 내보내기 → 이지원천에 업로드 *(권장)*
- **선택 B** — 자유 양식 엑셀 업로드 → AI가 컬럼 자동 매핑
- **선택 C** — 첫 달은 전원 신규로 시작 → 승인하면 자동 누적

<br/>

주민번호는 서버에서 **암호화 저장** — LLM에 절대 전송 안 함.

## [1~2] 세무사가 버튼 한 번 → 거래처 100곳에 일괄 발송

<div style="flex:1;">

**세무사 대시보드**

[자료 입력하기]  ← 포털 링크
```

거래처별 토큰 URL — 로그인 없이 그 거래처 화면만 열림.

## [3] 자료 수집 — 3가지 경로 (다 같은 파이프라인)

| 순위 | 경로 | 실무 시나리오 |
|------|------|------------|
| **1** | 세무사 직원이 거래처 카톡을 **이지원천 비즈채널로 공유** | 거래처와 기존 카톡 관계 유지 |
| **2** | 세무사 직원이 이메일을 `collect@` 로 포워딩 | 파일첨부·본문 그대로 |
| **3** | 대시보드에서 엑셀·사진 직접 업로드 | 폴백 |
| (옵션) | 거래처가 알림톡 링크 → 웹폼 직접 입력 | 규모 있는 거래처 |

<div class="callout small">

**왜 "직원 경유"인가**: 거래처 ↔ 이지원천 직접 연결은 상담 대응이 불가능해 폐기.
세무사무소가 신뢰 관계·오류 정정을 계속 담당한다.

</div>

---

## [4] AI 파싱 + 직원 매칭

**입력 예시**

```
김연호 100만원, 박민수 150, 이수정 저번달이랑 똑같아요
```

**AI가 하는 일**

- 이름·금액 추출 → 구조화 JSON
- 전월 DB와 매칭 (rapidfuzz 85점 이상 자동 매칭)
- 신규/퇴사 의심자 분리 → 자동 후속 질문 발송
- `"저번달이랑 똑같아요"` → 전월 데이터 자동 적용
- 이상치 감지 (1.5배 이상 변동 + 30만원 이상)

프로바이더: **Gemini Flash 2.5 메인 / Claude Sonnet 폴백**

## [4] 봇 응답 예시 — 파싱 결과 즉시 확인

✅ 하늘식품 9월 급여자료 접수 완료

[기존직원 5명]
· 박정수 5,400,000원
· 김미영 4,800,000원
· 이준호 3,700,000원

[신규 1명]
· 홍길동 2,000,000원

[퇴사 1명]
· 정하늘 (퇴사)

⚠️ 확인필요 1건

대시보드: https://이지원천.com/filings/xxx
```

세무사 직원이 카톡 안에서 바로 검증 → 거래처에 즉시 재확인 가능.

## [5] 세무사 검증·승인 대시보드

- **거래처별 상태 표시** — 수신완료 / 미수신 / 검증필요
- **이상치 하이라이트** — 전월 대비 급증·급감 자동 표시
- **화면 구조** — SmartA 급여대장 양식과 동일 (수당·공제·차인지급액)
- 세무사가 최종 승인해야 다음 단계로 넘어감

<div class="ok small">

**원칙**: AI는 초안까지만. 신고를 누르는 건 반드시 세무사(사람).

</div>

---

## [6] SmartA 급여대장 엑셀 자동 생성

- 인적사항·수당항목·공제항목·차인지급액 자동 계산
- **SmartA 급여대장 양식과 100% 호환** → 그대로 SmartA에 업로드 가능
- Phase 1에서는 세무사가 다운받아 SmartA에 수동 업로드
- Phase 2부터는 위하고 T로 자동 입력

<br/>

**데이터 표준** — SmartA 24컬럼이 저장·화면·엑셀의 단일 기준.

---

## [7] 위하고 T 자동 입력 — 이지원(지원이)이 담당 · Phase 2

<div class="callout">

**전용 노트북 "이지원" 방식** — 클라우드 서버에 로그인 정보·공동인증서를 절대 두지 않는다.

</div>

- 직원이 이지원천에서 **'위하고 전송'** 클릭 → 서버에 작업 등록
- 사무소에 있는 **이지원(지원이)** 이 HTTPS 폴링으로 작업을 가져감
- 지원이 크롬에 CDP 연결(Playwright) → 세무사 전용 아이디로 위하고 T 조작
- 자동화 범위 — **급여자료 입력 → 원천세 → 지방세**
- **사원등록(입·퇴사)은 자동화 제외** — 민감정보라 직원이 직접 입력
- 단계별 검증 — 상호·사업자번호·인원·총지급액·세액 대조 후 불일치면 중단

<div class="small muted">

"이지원"은 사무소용 노트북 1대(또는 미니PC). BitLocker + 전용 Windows 계정 + 세무사 전용 아이디로 세션 분리.

</div>

---

## [8] 홈택스·위택스 신고 + 접수증 자동 배송

**신고 승인 → 완료 → 거래처 안내까지**

1. 위하고 작업 완료 알림 → 세무사가 이지원천에서 **'신고'** 클릭 (승인)
2. 지원이가 홈택스에서 원천세 신고 → 성공 시 위택스에서 지방소득세 신고
3. 접수증·납부서 PDF 자동 회수 → 서버 `ClientFilingResult` 등록
4. **사장님 포털**에 자동 반영 + 납부안내 문자 발송

```
[○○세무] △△상사 대표님, 9월 원천세 신고가 완료되었습니다.
· 납부금액: 1,234,560원
· 납부기한: 10월 10일
[접수증 확인] ← 포털 보관함
```

## 번들 피처 ① 급여(임금)명세서 자동 교부

- 신고 데이터로 **근로기준법 제48조** 양식 자동 생성
- 수임처 직원에게 알림톡·문자로 **자동 발송**
- 수임처 사장님 추가 작업 = 0

<div class="warn small">

**시장 배경** — 의무화 3년 지났는데 직장인 23.8%가 아직 못 받고 있음. 숙박·음식점업은 48.5% 미교부.
과태료 1차 30만원 → 2차 50만원 → 3차 100만원 (직원 1명당 매월 별도).

</div>

**세무사 영업 무기** — *"저희에게 맡기면 명세서 교부 의무도 자동으로 해결됩니다"*

---

## 번들 피처 ② 4대보험 신고서 3종 엑셀

Phase 1에서 선구현, EDI 자동신고는 Phase 2~3.

- 자격**취득** 신고서
- 자격**상실** 신고서
- 보수월액 **변경** 신고서

세무사가 다운받아 4insure·공단 EDI에 업로드하는 수준까지 자동화.
Phase 3에서 RPA로 자동 제출로 확장.

## 로드맵 요약

| Phase | 기간 | 핵심 산출물 |
|-------|------|------------|
| **Phase 1** | 0~6개월 | 다채널 자료수집 + SmartA 급여대장 엑셀 + 급여명세서 번들 |
| **Phase 2** | 6~12개월 | 이지원(지원이) RPA — 위하고 T → 홈택스·위택스 + 접수증 포털·발송 |

Phase 1만 돌아도 **고객 응대 시간 80% 절감** — SmartA 업로드 1회로 끝난다.

</div>

## 차별화 포인트

1. **1단계(고객 소통·자료 수집) AI 자동화** — 경쟁사가 못 푼 영역
2. **급여명세서 자동 교부** — NAHAGO 대비 핵심 차별점
3. **전용 노트북 "이지원"** — 클라우드 서버에 로그인·인증서 저장 안 함 (보안·약관)
4. **SmartA 24컬럼 호환** — 세무사가 지금 쓰는 데이터 구조 그대로
5. **AI 프로바이더 이중화** — Gemini 메인 / Claude 폴백, 프롬프트 인젝션·서비스 장애 대비

# 문자 발송 구조 변경

## 알리고 API를 세무사무소가 직접 등록하는 방식

---

## 배경 — 왜 이 얘기를 하는가

**지금 구조 (초기 설계)**
- 이지원천이 알리고 마스터 계정 하나로 전 세무사무소 문자를 대신 발송
- 발신번호도 이지원천 명의로 고정
- 발신 비용을 이지원천이 부담 or 세무사에 재청구

**바꾸려는 이유**
1. **부가통신사업자 등록 리스크** — SaaS가 문자를 대신 발송하면 특수유형 부가통신 등록 대상 여지
2. **발신번호 신뢰도** — 사장님 폰에 이지원천 번호가 뜨면 스팸 인식
3. **회계·정산 단순화** — 문자 요금을 사업 비용에서 완전히 분리

---

## 새 구조 — "세무사무소 본인 계정에 API 키만 꽂는다"

```
[세무사무소]                          [이지원천]                     [알리고]
     │                                     │                          │
① 알리고 가입 + 이용계약 ─────────────────────────────────────►│
② 본인 명의 번호 발신번호 등록 ─────────────────────────────►│
③ 요금 본인 계정에 직접 충전 ──────────────────────────────►│
④ 발급받은 API 키 ─────────────────────►│                          │
                                        │                          │
                                        │ (프로그램에 API 키 입력)  │
                                        │                          │
[세무사가 대시보드에서 발송 클릭] ────►│ ─── API 키로 발송 요청 ──►│
                                        │                          │
                                        │◄── 발송 결과 ────────────│
                                        │                          │
                                        │ (요금은 세무사무소 계정에서 차감)
```

이지원천은 **"발송 도구"** 역할만 — 문자 비용을 일절 받지 않음.

---

## 새 구조의 4가지 원칙

| # | 원칙 |
|---|-----|
| ① | 각 세무사무실이 **알리고에 직접 회원가입** 및 이용계약 체결 |
| ② | 세무사무실 **본인 명의 번호**를 본인 계정에 발신번호로 등록 |
| ③ | 문자 요금은 각 세무사무실이 **본인 계정에 직접 충전** — 이지원천은 문자 요금 일절 미청구 |
| ④ | 세무사무실이 발급받은 **API 키를 이지원천 프로그램에 입력** → 프로그램은 해당 계정으로 발송 요청하는 도구 역할만 |

---

## 알리고에 확인 필요한 문의사항 4가지

**① 부가통신사업자 등록 필요 여부**
위 구조(세무사무실이 본인 계정에서 발송)에서도 이지원천이 **특수유형 부가통신사업자 등록**을 해야 하는지.

**② 다중 계정 공통 서버 IP 등록 가능 여부**
발송 요청이 이지원천 서버를 거치므로 여러 세무사무소 계정에 **동일한 발송 서버 IP(이지원천 서버)** 를 등록해야 함. 이 형태의 이용이 가능한지.

**③ ①·② 불가 시 대안**
등록 없이 이용 가능한 **SaaS 파트너 프로그램·연동 방식**이 있는지.

**④ 이지원천 자체 발송 (별건)**
이지원천 회사 명의 번호로 **저희 고객(세무사무실)에게** 서비스 알림(가입 인증, 신고기한 안내 등)만 발송하는 경우 — 현재 계정으로 등록 없이 이용 가능한지.
